# 중앙 ‘내 방식 QR’ — QR v5 설정·AI 추천·체험형 미리보기 구현

현재 작업 대상은 중앙 QR 사이트 **‘내 방식 QR’** Replit 프로젝트입니다.

서비스 주소: `https://naebangsikqr.replit.app`

현재 중앙 사이트는 QR 프로필 스키마 v4를 사용하며, 데모커피와 무인민원발급기의 공통 접근성 SDK는 **v0.5.31**까지 개발·검증됐습니다.

이번 작업의 목표는 중앙 사이트를 **QR 프로필 v5**로 확장하고, 새 설정인 `scrollGuidance`를 사용자가 선택·저장·불러올 수 있도록 하며, 사용자가 QR을 만들기 전에 실제로 설정을 체험할 수 있는 미리보기를 구현하는 것입니다.

**중요: 이번 작업은 중앙 QR 사이트에 한정됩니다. AI 실시간 키오스크 화면 변환 엔진 개발, 데모커피·무인민원발급기 수정, 모바일 QR 역방향 접속 기능 구현은 이번 범위가 아닙니다.**

## 1. 작업 전 현황 확인

실제 코드를 먼저 확인하세요. 이전 조사에서 확인한 주요 파일은 다음과 같습니다.

- `src/lib/profile.ts` — `ProfilePreferences`, `PROFILE_SCHEMA_VERSION`
- `src/App.tsx` — `SettingsForm`, `Preview`, 기본 설정, 프로필 변경·저장
- `src/index.css` — 미리보기 스타일 및 반응형 레이아웃
- `src/AIRecommendationFlow.tsx` — AI 추천 질문 흐름
- `server/recommendation.ts` — OpenAI Responses API 추천 스키마·매핑
- `server/app.ts` — 프로필 생성·조회·수정 API
- `server/schema.sql` — DB 관련 스키마
- 관련 테스트 파일

파일명이 다르거나 구조가 변경됐다면 실제 코드를 기준으로 진행하세요.

기존 설정과 공개 QR 생성·관리 기능을 유지하면서 최소한으로 수정해야 합니다.

## 2. QR 프로필 스키마 v5

기존 `PROFILE_SCHEMA_VERSION`을 **5**로 확장하고 다음 필드를 추가하세요.

`scrollGuidance: boolean`

의미:

- `true`: 스크롤 가능한 화면의 아래쪽 내용 안내를 활성화
- `false`: 비활성화

기본값은 **반드시 false**입니다.

다음 정책을 유지하세요.

| 프로필 | 적용 |
|---|---|
| QR 미적용 | OFF |
| v1~v4 기존 QR | OFF |
| v5에서 필드 누락 | OFF |
| v5 `scrollGuidance:false` | OFF |
| v5 `scrollGuidance:true` | ON |

SDK v0.5.31에서는 **v5에서 명시적으로 true인 경우에만** 스크롤 안내가 활성화되도록 검증됐습니다.

중앙 사이트도 이 정책과 정확히 일치해야 합니다.

주의사항:

- 기존 QR의 누락 필드를 true로 보정하지 마세요.
- 기존 설정값을 불필요하게 변경하지 마세요.
- `viewportMode:null`은 그대로 유지하세요.
- 쉬운 말 설정과 스크롤 안내 설정을 묶지 마세요.
- QR 프로필의 다른 필드는 기존 형식을 유지하세요.
- 잘못된 타입의 `scrollGuidance`를 조용히 true로 변환하지 마세요.
- 새 프로필을 생성할 때 실제 저장·반환되는 데이터가 v5와 일치해야 합니다.

서버의 다음 경로에서도 v5 일관성을 확인하세요.

- `POST /api/profiles`
- `POST /api/profiles/resolve`
- `GET /api/profiles/:id/manage`
- `PATCH /api/profiles/:id`

기존 v1~v4 프로필은 호환성을 유지하고, `scrollGuidance`가 없으면 false로 해석하세요.

**기존 QR 프로필이나 Production DB의 데이터를 삭제·일괄 변경하지 마세요.**

DB 구조상 v5에 필요한 스키마 또는 제약조건 변경이 발견되면 다음 원칙을 적용하세요.

- 개발 환경에서 안전하게 가능한 범위의 코드·스키마 파일 수정은 허용합니다.
- Production DB에 직접 적용하거나 기존 데이터를 수정하지 마세요.
- 현재 운영 DB에 별도의 마이그레이션이 필요한 경우 실행하지 말고, 필요한 SQL과 영향 범위를 최종 보고에 명시하세요.
- `schema.sql`이 서버 시작 시 자동 적용되는지 반드시 확인하고, Production에 간접적인 변경이 일어나지 않도록 하세요.
- Production 수정이 필요한 부분만 보류하고 나머지 개발·테스트를 진행하세요.

## 3. 새로운 사용자 설정 추가

설정 화면에 다음 항목을 추가하세요.

**설정 이름: 아래쪽 내용 안내**

설명:

“화면 아래에 더 볼 내용이 있으면 알려줘요. 끝까지 내리면 안내가 사라져요.”

ON/OFF 설정으로 제공하고 기본값은 **OFF**입니다.

사용자는 언제든 직접 변경할 수 있어야 합니다.

반드시 확인할 동작:

- 새 QR 생성 시 기본 OFF
- ON으로 변경 후 저장하면 true
- OFF로 변경 후 저장하면 false
- 저장된 프로필을 다시 열어도 값 유지
- 기존 QR을 불러오면 기본 OFF
- 다른 설정을 수정해도 값 유지
- 쉬운 말 안내 ON/OFF와 관계없이 독립적으로 동작

설정명과 설명은 사용자에게 보이는 문구이므로 위 표현을 사용하고, 별도 승인 없이 새로운 설정을 추가하지 마세요.

## 4. AI 접근성 설정 추천에 반영

기존 중앙 사이트의 AI 추천은 실제 OpenAI Responses API를 사용합니다.

기존 질문 흐름과 추천 방식은 유지하되, 아래쪽 내용 안내에 대한 판단을 추가하세요.

질문 문구:

**“화면 아래에 더 볼 내용이 있다는 안내가 필요하신가요?”**

사용자의 답변이 AI 추천에 반영되어 `scrollGuidance`에 true 또는 false가 추천되도록 하세요.

기본 정책:

- 사용자가 필요하다고 답하면 ON을 추천할 수 있음
- 필요 없다고 답하면 OFF를 추천
- 정보가 부족하면 기본 OFF
- AI 추천은 최종 결정이 아니며 사용자가 직접 수정할 수 있음

기존 AI 추천 결과 스키마·검증·파싱·후처리도 v5에 맞게 수정하세요.

다음 원칙을 유지해야 합니다.

- 기존 OpenAI Responses API 사용 방식 유지
- `store:false` 등 기존 개인정보 보호 정책 유지
- 민감정보 저장·로그 추가 금지
- AI 추천 실패 시 기존 안전한 기본 설정 제공
- AI 추천 결과가 잘못되거나 필드가 누락돼도 서비스 전체가 중단되지 않도록 처리
- 관련 테스트에서는 실제 유료 API 호출 대신 mock 사용
- 이미 존재하는 다른 AI 추천 질문이나 기능을 임의 삭제하지 않기

**중요: 이번 AI 작업은 ‘접근성 설정 추천’만 확장하는 것입니다. 키오스크 화면 자체를 AI가 분석·변환하는 엔진은 다음 단계에서 별도로 개발합니다.**

## 5. 미리보기를 세로 9:16 화면으로 변경

현재 중앙 사이트의 미리보기는 키오스크 화면을 단순화한 모의 UI이고, 기존 `.kiosk-screen`은 고정 높이 중심의 비교적 정사각형 형태입니다.

이 부분을 실제 세로형 키오스크에 가까운 **9:16 비율**로 변경하세요.

요구사항:

- 세로형 9:16 비율
- PC에서는 적절한 최대 너비 유지
- 휴대폰에서는 화면 너비에 맞게 축소
- 화면 바깥으로 잘리지 않기
- 내용과 조작 버튼이 보이도록 구성
- 기존 설정 화면과 공개 프로필 화면의 미리보기 모두 정상 표시
- 글씨·버튼 크기, 고대비, 하단 배치 등 기존 미리보기 반영 기능 유지

이번 미리보기는 **설정 효과를 보여주는 체험용 샘플**입니다.

실제 민원 발급이나 카페 주문 업무를 중앙 사이트에 새로 구현하지 마세요.

또한 미리보기만을 위해 중앙 사이트에 공통 SDK 전체를 새로 설치하거나, 데모커피·무인민원발급기의 업무 코드를 복사하지 마세요.

기존 중앙 사이트의 Preview 컴포넌트를 확장하는 방향으로 구현하세요.

## 6. 쉬운 말 안내를 실제로 조작할 수 있게 구현

`easyLanguage:true`라면 미리보기에서 쉬운 말 안내가 표시되어야 합니다.

단순히 설명 문구 하나를 보여주는 정적 화면이 아니라, 사용자가 실제로 이전·다음 버튼을 누를 수 있어야 합니다.

구현 내용:

- 쉬운 말 연습용 설명 2~3페이지
- 이전 버튼
- 다음 버튼
- `1/3`, `2/3`, `3/3` 등의 페이지 표시
- 마지막 페이지에서 더 진행하지 않도록 처리
- 첫 페이지에서 이전 버튼 비활성화
- 페이지를 이동해도 설명이 누락되지 않음
- 키보드와 터치로 모두 조작 가능
- 기존 글씨·버튼 크기 설정 반영
- 접기·펼치기 버튼 없음
- 쉬운 말 안내 자체의 X 종료 버튼 없음

연습 문구는 간단하고 이해하기 쉬운 예시로 구성하세요.

실제 주민등록표 발급 안내처럼 오인할 수 있는 업무 내용을 사용하지 마세요.

안내 문구 예시:

“다음 버튼을 눌러 이어지는 설명을 읽어보세요.”

중요:

**사용자가 보고 있던 쉬운 말 페이지는 스마트 길잡이가 표시됐다가 종료되어도 그대로 유지되어야 합니다.**

## 7. 스마트 길잡이 체험

`smartGuide:true`인 경우 미리보기에서도 스마트 길잡이의 동작을 실제로 체험할 수 있게 구현하세요.

스마트 길잡이는 쉬운 말 안내와 별개로 켤 수 있어야 합니다.

기존 SDK의 주요 동작 정책을 체험 화면에 반영하세요.

### 등장 시간

기존 설정값인 `guideDelaySeconds`를 따릅니다.

- 10초
- 15초
- 20초

스마트 길잡이를 ON으로 설정한 뒤 해당 지연 시간이 지나면 등장합니다.

### 안내 표시 시간

기본 안내:

- 1페이지: 10초
- 2페이지: 총 15초
- 2페이지라면 약 7.5초 시점에 다음 페이지로 자동 전환

느린 안내:

- 1페이지와 2페이지 모두 총 20초 기준
- 2페이지라면 약 10초 시점에 다음 페이지로 자동 전환

기존 SDK의 검증된 동작과 일치하게 구성하세요.

### 종료 방식

- 접기·펼치기 버튼 없음
- **X 버튼으로 종료**
- 설정된 시간이 끝나면 자동 종료
- 종료하면 쉬운 말 안내가 보이던 원래 페이지로 복귀
- 같은 체험 실행에서는 X로 닫은 스마트 길잡이가 다시 나타나지 않음
- 안내가 자동 종료된 경우에도 같은 실행에서 반복 등장하지 않음
- 쉬운 말 안내가 OFF여도 스마트 길잡이를 독립적으로 체험 가능

### 체험 다시 시작하는 방법

별도의 **‘스마트 길잡이 다시 연습하기’ 버튼은 만들지 마세요.**

기존 스마트 길잡이 설정을 OFF 했다가 다시 ON 하면 새로운 체험으로 간주하고 설정된 지연 시간부터 다시 시작하도록 하세요.

설정 OFF 시 기존 타이머와 안내를 정리하고, ON 시 새 타이머를 시작해야 합니다.

설정값 변경, 컴포넌트 재렌더링 때문에 같은 체험에서 타이머가 중복 시작되지 않도록 구현하세요.

### 체험 도움말

다음과 같은 짧은 문구를 미리보기 주변에 표시할 수 있습니다.

- “스마트 길잡이가 나타나면 X 버튼을 눌러 닫아보세요.”
- “스마트 길잡이를 닫으면 읽던 쉬운 말 안내로 돌아와요.”

과도한 설명문이나 별도 재시작 버튼은 추가하지 마세요.

## 8. 자동 하단 80% 미리보기 오류 수정

현재 미리보기에는 다음과 같은 계산이 존재하는 것으로 조사됐습니다.

`preferences.viewportMode?.heightPercent ?? 100`

이 때문에 쉬운 말 안내를 ON으로 설정하면서 화면 배치를 별도로 선택하지 않은 경우에도 미리보기에서는 전체 화면 100%로 표시되는 문제가 있습니다.

실제 SDK의 정책은 다음과 같습니다.

| 조건 | 실제 사용 영역 |
|---|---|
| 쉬운 말 OFF + viewportMode:null | 100% |
| 쉬운 말 ON + viewportMode:null | 하단 80% |
| viewportMode:하단 60% | 60% |
| viewportMode:하단 70% | 70% |
| viewportMode:하단 80% | 80% |

미리보기도 동일하게 동작하게 수정하세요.

**중요: 쉬운 말 ON이라고 실제 저장값 `viewportMode:null`을 80%로 바꾸면 안 됩니다.**

이는 표시 계산에만 적용되는 자동 정책입니다.

하단 60·70·80% 설정을 사용자가 직접 선택한 경우에는 해당 설정을 우선 적용하세요.

사용자에게 불필요하게 혼란을 주는 “직접 바꿀 수도 있어요” 등의 문구는 새로 추가하지 마세요.

## 9. 아래쪽 내용 안내 미리보기

`scrollGuidance:true`인 경우 미리보기에서 스크롤 안내를 체험할 수 있어야 합니다.

단순한 그림이나 항상 표시되는 고정 문구가 아니라, **실제 스크롤 상태에 따라 표시가 달라지는 안내**로 구현하세요.

반드시 다음을 만족해야 합니다.

- `scrollGuidance:false`면 항상 OFF
- `scrollGuidance:true`이고 실제로 아래에 더 볼 내용이 있으면 ON
- 끝까지 스크롤하면 사라짐
- 다시 위로 스크롤하면 나타남
- 안내는 스크롤 입력을 가로채지 않음
- 스크롤 영역의 내용을 자연스럽게 볼 수 있음
- 일반적인 스크롤 콘텐츠와 겹치는 것은 허용
- 고정 QR 버튼 또는 footer가 있다면 그 위를 덮지 않도록 배치
- 쉬운 말 안내 ON/OFF와 독립적으로 동작

실제 스크롤이 발생할 만큼 충분한 샘플 콘텐츠를 제공하세요.

설명을 위해 기존 키오스크 업무 내용을 많이 추가하지는 마세요.

체험 도움말 예시:

“화면을 끝까지 내리면 아래쪽 내용 안내가 사라져요.”

## 10. 기존 기능 유지

새 기능 구현 때문에 다음 기능이 바뀌어서는 안 됩니다.

- 기존 QR 생성
- QR 프로필 조회·수정
- QR 이미지 및 관리 기능
- 글씨 크기 설정
- 버튼 크기 설정
- 고대비
- 하단 배치 60·70·80%
- 쉬운 말 설정
- 스마트 길잡이 설정
- 언어 설정
- 단계별 안내·간결한 안내
- 기존 AI 추천 흐름
- 설정 저장 후 미리보기 반영
- 모바일 반응형 레이아웃
- 기존 QR의 프로필 호환성

관련 없는 문구, 디자인, 업무 흐름을 임의 변경하지 마세요.

## 11. 테스트

가능한 기존 테스트 체계를 활용하되, 이번에 추가한 동작은 반드시 검증하세요.

### 프로필 및 API

- v5 프로필 생성·조회·수정
- `scrollGuidance` true/false 저장
- v5 필드 누락 시 false
- v1~v4 false
- 다른 설정을 수정한 뒤에도 값 유지
- 스키마와 API의 일관성

### AI 추천

- 새로운 질문 표시
- ON 추천
- OFF 추천
- 답변이 불명확할 때 기본 OFF
- 추천 결과를 사용자가 수정 가능
- API 실패 시 안전한 기본값
- 실제 유료 API 호출 없는 mock 테스트

### 미리보기

- 9:16 비율
- 좁은 모바일 화면에서 잘리지 않음
- 글씨·버튼 설정 반영
- 쉬운 말 1→2→3→2→1 페이지 조작
- 스마트 길잡이 등장 지연
- X 종료·자동 종료
- 기존 쉬운 말 페이지 복귀
- OFF→ON으로만 스마트 길잡이 재시작
- 스마트 길잡이 OFF일 때 타이머·패널 정리
- 자동 하단 80%
- 명시적 60·70·80%
- 스크롤 안내 ON/OFF
- 스크롤 끝에서 숨김·되올리기
- 고정 조작부와 겹침 없음

브라우저 테스트에서는 가능한 경우 360×667, 390×844 화면을 대표 크기로 확인하세요.

스마트 길잡이의 긴 타이머는 테스트용 가상 시간 또는 fake timer를 활용해 불필요한 대기 시간을 줄이세요.

### 빌드

- 타입 검사
- 기존 단위 테스트
- 서버 테스트
- 프런트엔드 빌드

테스트가 실행되지 않거나 미검증 항목이 있다면 성공했다고 주장하지 말고 정확히 보고하세요.
