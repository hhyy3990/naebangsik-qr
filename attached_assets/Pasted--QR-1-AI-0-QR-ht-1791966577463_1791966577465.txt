# 내 방식 QR — 1차 AI 맞춤 접근성 프로필 추천 기능 개발

## 0. 작업 대상 및 원칙

현재 프로젝트는 중앙 **'내 방식 QR' 홈페이지**입니다.

사이트: https://naebangsikqr.replit.app

데모커피 또는 무인민원발급기 프로젝트가 아닙니다.

현재 중앙 서비스에는 QR 프로필 v3 기반의 설정 선택, 미리보기, QR 생성·조회·수정·폐기·재발급 기능이 구현되어 있습니다.

이번 작업에서는 **AI가 사용자의 불편함을 분석해 기존 접근성 설정을 추천하고, 사용자가 추천 결과를 확인하면 실제 설정 버튼이 자동으로 변경되는 기능**을 구현합니다.

### 반드시 지킬 원칙

- 기존 QR v3 프로필 구조 유지
- 기존 QR 생성·관리 기능 유지
- 실제 생성형 AI API 사용
- AI 추천 결과를 기존 설정 UI에 연결
- AI 추천 없이 직접 설정하는 기능 유지
- 개인정보 최소 수집 및 민감정보 전송 차단
- 기존 홈페이지 디자인과 접근성 유지
- 중앙 운영 DB 스키마 변경 금지
- Publish 금지

이번에는 **AI 추천 기능만 개발**합니다. 새로운 스마트 길잡이 UI나 미리보기 연습 기능은 구현하지 않습니다.

## 1. 기존 프로젝트 분석

개발 전에 현재 프로젝트 구조를 확인하세요.

특히 다음을 조사합니다.

1. 홈페이지의 QR 생성 단계 및 설정 화면
2. 기존 접근성 설정을 관리하는 상태와 타입
3. QR v3 생성·수정·저장 API
4. 기존 미리보기와 설정값의 연결 구조
5. 서버의 AI 연동 여부 및 환경변수
6. 개인정보 검사·API 보안·에러 처리
7. 기존 자동화 테스트 및 브라우저 테스트 구성

새 기능을 위해 기존 정상 작동 코드를 불필요하게 교체하지 마세요.

기존 API·컴포넌트·유틸리티를 가능한 한 재사용합니다.

## 2. 홈페이지 진입 방식

QR 설정을 시작할 때 두 가지 경로를 제공합니다.

### 첫 번째 — AI 추천받기

제목:

**AI 추천받기**

설명:

**몇 가지 질문에 답하면 나에게 맞는 설정을 추천해 드려요.**

### 두 번째 — 직접 설정하기

제목:

**직접 설정하기**

설명:

**글씨와 버튼 크기 등을 내가 직접 고를 수 있어요.**

### 배치 규칙

데스크톱에서는:

- 왼쪽: AI 추천받기
- 오른쪽: 직접 설정하기

모바일에서는:

- 위쪽: AI 추천받기
- 아래쪽: 직접 설정하기

AI 추천받기를 주요 선택지로 표현하되, 직접 설정하기도 쉽게 찾을 수 있게 합니다.

두 경로는 서로 다른 QR을 만드는 것이 아닙니다.

**최종적으로 동일한 기존 설정 UI와 QR 생성 기능을 사용해야 합니다.**

기존 홈페이지의 핵심 단계 안내와 프로필 관리 기능을 제거하지 마세요.

## 3. AI 추천 질문지 — 확정된 5개 질문

질문은 기존 키오스크 사용 경험을 기준으로 작성합니다.

사용자가 '내 방식 QR'의 기능을 미리 알고 있다는 전제를 두지 마세요.

모든 질문은 선택 사항입니다.

해당하는 선택지가 없다면 비워둘 수 있고, 자유 입력도 생략할 수 있습니다.

### 질문 ① 연령대

**연령대를 알려주세요.**

단일 선택:

- 20대 이하
- 30~50대
- 60대
- 70대
- 80대 이상
- 선택하지 않을래요

연령대는 AI 추천에 참고 정보로만 사용합니다.

나이를 근거로 특정 시력·장애·이해 능력을 단정하지 마세요.

### 질문 ② 선호 언어

**어떤 언어로 안내받고 싶으신가요?**

단일 선택:

- 한국어
- 중국어 (中文)
- 베트남어 (Tiếng Việt)
- 영어 (English)
- 태국어 (ภาษาไทย)
- 우즈베크어 (Oʻzbekcha)
- 일본어 (日本語)

기본값은 한국어입니다.

아래에 다음 문구를 표시하세요.

**이 외의 언어는 추후 추가할 예정입니다.**

중요: 다국어 QR 프로필 및 키오스크 번역 기능은 아직 정식 구현 전입니다.

이번 단계에서 사용자의 선호 언어는 **AI 추천 입력과 화면 내 향후 지원 안내에만 활용**합니다.

QR v3에 존재하지 않는 언어 필드를 저장하거나 실제 다국어 키오스크 안내가 지원되는 것처럼 표시하지 마세요.

### 질문 ③ 화면을 보거나 누를 때

**키오스크 화면을 보거나 누를 때 어떤 점이 불편한가요?**

복수 선택:

- 작은 글씨가 잘 안 보여요.
- 글씨나 그림이 선명하지 않아요.
- 버튼이 작아서 누르기 어려워요.
- 화면 위쪽까지 손이 닿지 않아요.
- 어떤 버튼을 눌러야 할지 모르겠어요.

선택지의 수와 문구는 임의 변경하지 마세요.

### 질문 ④ 안내와 이해에 관하여

**키오스크를 사용할 때 어떤 점이 어렵거나 불편한가요?**

복수 선택:

- 어려운 단어가 많아요.
- 무엇부터 해야 할지 헷갈려요.
- 화면에 나온 내용을 이해하는 데 시간이 오래 걸려요.
- 글보다 말로 알려주는 게 편해요.

특히 세 번째 문구는 정확히 유지하세요.

이 선택지는 추후 스마트 길잡이의 표시 시간을 10초에서 15초로 늘리는 기능과 연계할 예정입니다.

현재 QR v3에는 표시 유지 시간 설정이 없으므로, **기존 guideDelaySeconds를 15초 유지 시간으로 잘못 사용하는 일이 없어야 합니다.**

### 질문 ⑤ 자유 입력

**더 알려주고 싶은 점이 있나요?**

안내:

**없다면 비워두셔도 돼요.**

예시 입력:

**작은 글씨는 불편하지만 설명은 짧은 게 좋아요.**

자유 입력은 선택 사항이며 적절한 글자 수 제한을 둡니다.

민감정보를 입력한 경우 AI 서버로 전송하지 않습니다.

## 4. 실제 AI 추천 기능

**이번 기능에는 실제 생성형 AI 호출이 반드시 포함되어야 합니다.**

질문 응답을 몇 개의 조건문으로만 처리하고 AI 추천이라고 표시하지 마세요.

먼저 현재 프로젝트에서 사용 가능한 AI 연동 환경과 서버 설정을 확인합니다.

가능하다면 기존 AI 연동 및 환경변수를 재사용합니다.

AI API 키는 반드시 서버 측에만 보관합니다.

### AI 추천의 역할

- 복수의 불편함 종합 분석
- 자유 입력의 의미 파악
- 명시되지 않은 보조 접근성 설정도 합리적으로 추천
- 충돌하는 요구사항 감지
- 지원되는 설정만 반환
- 추천 이유를 쉬운 말로 설명
- 사용자의 선택을 존중하고 과도한 추론 방지

예를 들어 사용자가 '작은 글씨가 잘 안 보여요'와 '버튼이 작아서 누르기 어려워요'를 동시에 선택했다면 글씨와 버튼 확대를 함께 검토합니다.

화면 위쪽까지 손이 닿지 않는 경우에는 하단 조작을 검토합니다.

AI가 반드시 모든 설정을 켜도록 만들지 마세요.

## 5. QR v3의 실제 지원 설정만 사용

현재 QR v3의 정확한 타입과 기존 설정 UI를 확인한 후 다음 값을 활용합니다.

- textSize: standard / large / extraLarge
- buttonSize: standard / large
- contrast: standard / high
- easyLanguage: boolean
- smartGuide: boolean
- guideDelaySeconds: 10 / 15 / 20
- voiceGuidance: boolean
- viewportMode: null 또는 bottom 60 / 70 / 80

**이미 제거된 화면 단순화 기능을 다시 도입하지 마세요.**

또한 다음 기능은 이번 단계에 실제 설정값으로 추가하지 않습니다.

- 새로운 선호 언어 QR 필드
- 순서대로 안내 선호
- 짧은 안내 선호
- 천천히 안내받기 15초 유지 설정

이 기능들은 이후 QR 스키마·공통 SDK 확장 때 구현합니다.

AI는 앞으로 지원할 기능과 지금 실제로 적용 가능한 기능을 명확하게 구분해야 합니다.

특히 `guideDelaySeconds`의 10/15/20초는 **스마트 길잡이가 나타나기 전의 대기 시간**입니다.

표시 후 10/15초 유지와 혼동하지 마세요.

'화면에 나온 내용을 이해하는 데 시간이 오래 걸려요'를 선택했더라도, 아직 없는 15초 유지 기능을 적용했다고 표시하면 안 됩니다.

현재 지원되는 쉬운 말·스마트 길잡이 등의 설정을 추천하고, 추후 지원할 항목은 별도로 안내할 수 있습니다.

## 6. 추천 결과의 검증

AI는 검증 가능한 구조화된 데이터를 반환해야 합니다.

서버에서는 다음을 검증합니다.

- 설정 필드명
- 허용된 enum 값
- boolean 타입
- 하단 조작 설정 범위
- 추천 이유 문장 길이
- 입력값과 추천 결과의 일관성

AI가 임의 CSS, HTML, JavaScript, URL 또는 새로운 설정 필드를 전달해도 실행하거나 그대로 적용하지 않습니다.

AI 응답은 반드시 기존 설정 타입으로 변환·검증한 뒤 사용합니다.

AI 호출이 실패하면 기본 설정이나 기존 수동 설정 경로를 안전하게 이용할 수 있어야 합니다.

현재 프로젝트에 AI 호출 환경이 없다면 가짜 결과를 실제 AI 추천으로 가장하지 마세요.

필요한 API 환경 및 차단 원인을 보고합니다.

## 7. 개인정보 보호

다음 정보를 AI로 보내거나 로그에 남기지 않도록 합니다.

- 주민등록번호
- 카드번호
- 계좌번호
- 비밀번호
- 인증번호
- 기타 결제·금융 민감정보

자유 입력은 AI 요청 전 개인정보·민감정보를 검사합니다.

기존 프로젝트에 개인정보 차단 로직이 있다면 활용하고 필요한 경우 보강합니다.

패턴 기반 검사는 완벽하지 않으므로, 허용하지 않은 민감정보가 전송되지 않도록 입력 제한과 서버 측 검증을 함께 적용합니다.

AI 추천 질문지의 원문 응답, 연령대, 자유 입력 내용은 QR 프로필에 저장하지 않습니다.

중앙 서비스에는 사용자가 최종 승인한 접근성 설정만 기존 방식대로 저장합니다.

요청 횟수 제한, 중복 요청 방지, 응답 오류 처리도 구현합니다.

## 8. 추천 이유 표시

AI 추천 결과에 다음을 보여줍니다.

1. 추천한 설정
2. 추천 이유
3. 사용자가 설정을 직접 수정할 수 있다는 안내

추천 이유는 사용자가 선택한 어려움과 실제 적용 가능한 설정을 연결하는 짧고 자연스러운 문장으로 만듭니다.

예시:

**작은 글씨를 읽기 어렵다고 하셔서 글씨를 크게 설정했어요. 미리보기에서 편한 크기인지 확인해 보세요.**

**화면 위쪽 버튼에 손이 닿기 어렵다고 하셔서 조작 영역을 아래쪽으로 옮기도록 추천했어요.**

**어려운 표현을 쉽게 설명하고, 다음에 눌러야 할 버튼을 알려드리도록 추천했어요.**

연령대를 선택했다는 이유만으로 장애나 이해 능력을 추측하지 마세요.

실제로 적용하지 않은 설정을 추천 이유에 포함하지 마세요.

## 9. AI 추천값을 기존 설정 버튼에 자동 적용

**가장 중요한 개발 항목입니다.**

AI 추천 결과를 텍스트로 출력하는 데서 끝내지 마세요.

사용자가 **'이 설정 사용하기'** 버튼을 누르면:

1. AI 추천 결과의 유효성을 검사합니다.
2. 기존 QR 설정 상태에 추천값을 반영합니다.
3. 기존 글씨 크기·버튼 크기·고대비·하단 조작 등의 선택 버튼이 실제로 바뀝니다.
4. 기존 접근성 미리보기에도 즉시 반영합니다.
5. 사용자는 적용된 설정을 다시 수정할 수 있습니다.
6. 최종적으로 'QR 생성하기'를 누르면 수정된 설정으로 실제 QR을 생성합니다.

기존 설정 UI와 QR 생성 API를 그대로 사용합니다.

AI 추천 전용 별도 QR 저장 로직을 만들지 마세요.

AI 추천을 적용한 후 사용자가 직접 수정한 값을 자동으로 덮어쓰지 않도록 합니다.

AI 추천을 이용하지 않는 기존 사용자도 직접 설정 경로로 정상적으로 QR을 생성할 수 있어야 합니다.

## 10. UI 및 반응형 요구사항

현재 중앙 홈페이지의 디자인을 유지합니다.

- 웜그레이·오프화이트 등 기존 디자인 체계 유지
- 기존 폰트와 버튼 스타일 유지
- 320px 모바일 너비부터 정상 사용
- 큰 글씨 환경에서 텍스트 잘림 방지
- 선택지가 길면 자연스럽게 여러 줄 표시
- 체크박스·라디오 터치 영역 충분히 크게 제공
- 선택 항목을 취소하거나 수정하기 쉽게 구현
- AI 분석 중 로딩 상태 표시
- AI 실패 시 다시 시도 및 직접 설정으로 이동 가능
- 키보드 조작·스크린리더 접근성 고려
- 선택한 답변이 화면 전환 때문에 의도치 않게 사라지지 않도록 처리

AI 추천을 받지 않아도 QR 생성 화면으로 갈 수 있어야 합니다.

## 11. 이번에는 미리보기 연습 기능을 만들지 않습니다

향후 별도 단계에서 **'미리보기에서 직접 연습하기'** 기능을 개발할 예정입니다.

그 기능에는 다음이 포함됩니다.

- 쉬운 말 접기·펼치기
- 설명 항목 이전·다음
- 스마트 길잡이 10초 숫자 카운트다운
- 천천히 안내받기 15초
- 스마트 길잡이가 끝나면 이전 쉬운 말 항목으로 복귀
- 안내창을 접어둔 경우 접힌 상태 유지

이 기능들은 공통 SDK에서 실제 동작을 구현하고 검증한 후 중앙 홈페이지 미리보기에 연결합니다.

**이번 작업에서 가짜 연습 기능이나 동작하지 않는 버튼을 먼저 만들지 마세요.**

기존 접근성 미리보기는 그대로 보존합니다.

## 12. 필수 테스트

### AI 추천 질문지

- 홈페이지에서 AI 추천받기 진입
- 직접 설정하기 진입
- 모바일에서 AI 추천받기가 위에 표시
- 질문 5개 정확히 표시
- 연령대 단일 선택
- 언어 단일 선택
- 불편함 복수 선택·해제
- 건너뛰기 가능
- 자유 입력 생략 가능
- 자유 입력 길이 제한
- 선택 상태 정상 유지

### AI 추천 API

- 실제 모델 요청 및 응답
- 구조화된 응답 검증
- 허용하지 않은 설정값 차단
- 개인정보 입력 차단
- 중복 요청 차단
- AI 실패·타임아웃 처리
- 연령대만으로 부적절한 설정 강제하지 않음
- 지원하지 않는 기능 추천값 거부

### 기존 설정 연동

- 추천 결과 및 이유 표시
- '이 설정 사용하기' 클릭
- 실제 설정 버튼 선택 상태 변경
- 기존 미리보기 즉시 갱신
- 추천 적용 후 사용자가 직접 수정
- 최종 수정값으로 QR 생성
- QR 재조회 시 실제 저장값 일치
- AI 경로와 직접 설정 경로가 동일한 QR 생성 API 사용

### 기존 기능 회귀

- QR v3 생성·조회·수정·폐기·재발급
- 기존 v1/v2 QR 조회 호환성
- QR PNG 저장·링크 공유
- 기존 접근성 설정
- 개인정보 차단
- 타입 검사
- 프로덕션 빌드
- 실제 Preview 브라우저 테스트
- 브라우저 콘솔 오류 확인

API 테스트뿐 아니라 실제 브라우저에서 AI 추천 → 기존 설정 반영 → QR 생성 흐름을 확인하세요.
