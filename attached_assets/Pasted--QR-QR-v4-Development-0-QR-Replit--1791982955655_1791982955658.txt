# 내 방식 QR — QR 프로필 v4 개발 및 Development 호환성 검증

## 0. 작업 대상과 목적

현재 프로젝트는 중앙 **'내 방식 QR' Replit**입니다.

사이트: https://naebangsikqr.replit.app

현재 중앙 서비스는 QR 프로필 v3를 사용하며, OpenAI 기반 AI 맞춤 접근성 설정 추천 기능과 기존 QR 생성·조회·수정·폐기·재발급 기능이 구현되어 있습니다.

이번 작업은 QR 프로필을 **v4로 확장**하여 사용자의 언어와 안내 방식 선호까지 저장하고, 향후 공통 SDK에서 읽어 적용할 수 있도록 만드는 것입니다.

**가장 중요한 원칙은 기존 QR v1/v2/v3와의 하위 호환성을 유지하는 것입니다.**

이번 작업은 Development에서 구현하고 테스트하는 단계입니다.

Production DB 마이그레이션이나 Publish는 진행하지 마세요.

---

## 1. 기존 v3 구조부터 조사

코드 수정 전에 다음을 먼저 확인하세요.

- 현재 v3 프로필 타입 및 기본값
- DB의 profiles 테이블 구조와 제약조건
- QR 생성·조회·수정·폐기·재발급 API
- QR 토큰과 관리 권한 분리 구조
- 기존 v1/v2/v3 읽기·쓰기 호환성
- 중앙 QR 서버가 SDK에 전달하는 응답 형식
- AI 추천 결과가 설정 상태에 자동 반영되는 흐름
- 기존 설정 UI와 미리보기
- 현재 테스트와 마이그레이션 구조

**개발 DB와 Production DB의 스키마가 같다고 추측하지 말고, 실제로 확인 가능한 환경을 구분해 주세요.**

기존 데이터의 삭제, 초기화, 전체 테이블 재생성은 금지합니다.

## 2. v3 설정은 모두 유지

기존 QR v3 필드를 보존합니다.

- `textSize`: standard / large / extraLarge
- `buttonSize`: standard / large
- `contrast`: standard / high
- `easyLanguage`: boolean
- `smartGuide`: boolean
- `guideDelaySeconds`: 10 / 15 / 20
- `voiceGuidance`: boolean
- `viewportMode`: null 또는 `{ mode: "bottom", heightPercent: 60 | 70 | 80 }`

실제 저장된 타입과 API 계약을 먼저 확인하고 일치시켜 주세요.

**화면 단순화 기능은 이전에 제거했으므로 다시 추가하지 마세요.**

`guideDelaySeconds`의 의미도 변경하지 않습니다. 이것은 안내가 나타나기 전 기다리는 시간입니다.

## 3. v4 신규 설정 설계

v4에서는 다음 네 가지 사용자 선호를 추가합니다.

### A. 선호 언어

사용자에게 표시되는 설정명:

**안내 언어**

지원 언어:

- 한국어 — `ko`
- 중국어 — `zh`
- 베트남어 — `vi`
- 영어 — `en`
- 태국어 — `th`
- 우즈베크어 — `uz`
- 일본어 — `ja`

기본값은 한국어입니다.

아래 문구를 함께 표시하세요.

**이 외의 언어는 추후 추가할 예정입니다.**

언어 설정은 국적이 아닌 사용자가 실제로 편하게 사용하는 언어를 의미합니다.

향후 다른 키오스크에서도 동일한 값을 읽을 수 있도록 국제적으로 일반적인 언어 코드 사용을 우선합니다.

### B. 순서대로 안내받기

사용자에게 표시되는 설정명:

**순서대로 안내받기**

설명:

**해야 할 일을 하나씩 차례대로 알려드려요.**

켜기 / 끄기 설정.

AI가 스마트 길잡이 또는 쉬운 말 설명을 생성할 때, 해야 할 행동을 순서대로 설명하는 데 사용하는 선호 정보입니다.

### C. 짧은 설명 선호

사용자에게 표시되는 설정명:

**짧게 안내받기**

설명:

**꼭 필요한 내용만 짧게 알려드려요.**

켜기 / 끄기 설정.

순서대로 안내받기와 짧게 안내받기는 동시에 켤 수 있습니다.

두 설정이 동시에 켜지면 향후 AI는 짧고 순서가 분명한 안내를 생성해야 합니다.

### D. 천천히 안내받기

사용자에게 표시되는 설정명:

**천천히 안내받기**

설명:

**스마트 길잡이를 15초 동안 보여드려요.**

켜기 / 끄기 설정.

정책:

- OFF: 스마트 길잡이 표시 후 10초 유지
- ON: 스마트 길잡이 표시 후 15초 유지

이는 표시 전 대기 시간인 `guideDelaySeconds` 10/15/20초와 완전히 별개입니다.

**기존 `guideDelaySeconds` 값을 변경해서 15초 표시 기능을 구현하면 안 됩니다.**

실제 키오스크 SDK v0.5.11에서는 아직 15초 표시 유지 기능이 구현되지 않았으므로, v4에 값을 저장하더라도 실제 키오스크에 즉시 적용된다고 주장하지 마세요.

## 4. 데이터 구조 설계

v4 프로필에서 신규 네 설정을 어떤 필드로 저장할지 현재 코드 관례에 맞게 결정하세요.

권장 구조는 다음과 같습니다.

- `language`: 선호 언어 코드
- `stepByStepGuidance`: 순서대로 안내 여부
- `conciseGuidance`: 짧게 안내 여부
- `slowGuidance`: 천천히 안내 여부

정확한 내부 필드명은 기존 타입과 충돌하지 않는 범위에서 조정할 수 있으나, 한 번 결정한 필드명·타입·기본값을 문서화하고 모든 API에서 일관되게 사용해야 합니다.

### 하위 호환성

- v1 QR 조회 가능
- v2 QR 조회 가능
- v3 QR 조회 가능
- 신규 v4 QR 생성·조회·수정 가능
- v1~v3의 기존 설정 의미 유지
- 구버전 응답을 v4로 해석할 때 신규 설정은 안전한 기본값 사용
- 이전 프로필을 조회했다고 임의로 v4로 변경·저장하지 않음
- 구버전 QR의 `viewportMode`를 잘못 활성화하지 않음

호환성을 위해 구버전 읽기 경로와 v4 신규 프로필 생성 경로를 명확히 분리하세요.

## 5. 중앙 홈페이지 설정 UI

기존 접근성 설정 화면에 신규 설정을 자연스럽게 추가합니다.

### 안내 언어

한국어 및 여섯 외국어를 선택할 수 있는 단일 선택 UI.

현재 홈페이지의 스타일을 유지하세요.

### 순서대로 안내받기

ON/OFF 토글.

### 짧게 안내받기

ON/OFF 토글.

### 천천히 안내받기

ON/OFF 토글.

기존 쉬운 말·스마트 길잡이·음성 안내 설정과 혼동하지 않도록 짧은 설명을 함께 제공합니다.

스마트 길잡이를 OFF로 설정한 경우 천천히 안내받기의 효과가 없다는 점을 사용자에게 자연스럽게 안내하거나 관련 UI를 안전하게 비활성화하는 방법을 검토하세요.

다만 이전에 설정한 선호값이 조용히 삭제되는 일은 피하세요.

**QR 생성 전 설정 미리보기는 기존 동작을 유지합니다.**

이번 단계에서 새로운 스마트 길잡이 팝업이나 접기·펼치기 UI를 구현하지 마세요.

## 6. AI 맞춤 설정 추천과 연결

기존 OpenAI 기반 AI 추천 기능을 그대로 유지하면서 v4 필드에 대응하도록 확장합니다.

AI 추천에 활용할 수 있는 정보:

- 연령대
- 선호 언어
- 작은 글씨·작은 버튼 등 불편함
- 어려운 단어
- 어떤 버튼을 눌러야 할지 모름
- 무엇부터 해야 할지 헷갈림
- 화면 내용을 이해하는 데 시간이 오래 걸림
- 글보다 말로 알려주는 게 편함
- 선택적 자유 입력

### 권장 매핑

- 어려운 단어가 많음 → 쉬운 말 고려
- 무엇부터 해야 할지 헷갈림 → 스마트 길잡이 및 순서대로 안내 고려
- 화면 내용을 이해하는 데 시간이 오래 걸림 → 천천히 안내받기 고려
- 설명을 짧게 받기를 원함 → 짧게 안내받기 고려
- 선호 언어 선택 → 해당 언어 설정 반영

AI가 사용자의 연령대만으로 안내 방식이나 장애 특성을 단정하지 않도록 합니다.

80대 이상이면서 작은 글씨가 잘 안 보인다고 명시한 경우 `extraLarge`를 우선 추천하는 기존 규칙도 유지하세요.

AI 추천 응답은 v4 타입과 허용값을 서버에서 검증해야 합니다.

추천값이 생성되면 기존 동작대로 **즉시 설정 편집 상태에 반영**하고, 사용자에게 결과 요약 화면을 먼저 표시합니다.

'이 설정 사용하기' 버튼은 이미 반영된 설정을 확인·수정하는 화면으로 이동하는 역할을 유지합니다.

추천 이유는 결과 카드에만 표시하고 중복 출력하지 마세요.

## 7. 실제 지원 범위 안내

이번 단계는 중앙 QR 프로필이 신규 선호값을 저장하고 반환할 수 있도록 하는 작업입니다.

실제 키오스크 공통 SDK에 아직 구현되지 않은 기능:

- 다국어 안내 적용
- 순서대로 안내 생성
- 짧은 AI 설명 생성
- 스마트 길잡이 15초 표시
- 쉬운 말·스마트 길잡이 공통 안내창
- 접기·펼치기
- 설명 항목 이전·다음
- 숫자 카운트다운

이 기능들은 이후 **데모커피 프로젝트의 공통 SDK**에서 개발할 예정입니다.

홈페이지에서는 새 설정을 선택하고 저장할 수 있지만, 연결된 키오스크에 즉시 적용된다고 오해할 표현은 피하세요.

필요하다면 다음과 같은 짧은 안내를 추가하세요.

**새 안내 설정은 지원 키오스크에 순차적으로 적용될 예정입니다.**

단, 이미 구현된 글씨 크기·버튼 크기 등의 기존 기능까지 미지원처럼 보이지 않도록 구분하세요.

## 8. DB 및 마이그레이션 안전성

현재 Development DB의 스키마를 확인하고, v4 지원에 필요한 최소 변경만 설계·적용하세요.

- 기존 프로필 데이터 삭제 금지
- 무조건적인 테이블 재생성 금지
- 기존 제약조건 확인
- 마이그레이션 재실행 안전성 검증
- 신규 기본값 검증
- 기존 v1/v2/v3 데이터 보존
- QR 관리 권한 및 토큰 구조 유지

**Production DB에는 어떤 SQL도 실행하지 마세요.**

Production 데이터 복사·마이그레이션·제약조건 변경을 실행하지 않습니다.

Production 적용을 위해 필요한 SQL과 검증 순서는 별도로 문서화해 보고만 하세요.

운영 환경에서 기존 v3 서비스와 신규 v4 서비스가 섞이는 경우의 호환성 위험도 검토하세요.

## 9. SDK 연동 계약 문서화

중앙 QR의 v4 응답을 공통 SDK에서 재사용할 수 있도록 API 계약을 문서화하세요.

반드시 포함할 내용:

- v4 전체 JSON 예시
- 신규 필드 타입·허용값
- 신규 필드 기본값
- 기존 v1~v3 응답과의 차이
- 이전 QR 호환성 정책
- 신규 언어 코드
- 표시 전 대기 시간과 표시 후 유지 시간의 차이
- 구버전 SDK에서 v4 QR을 조회할 때 발생할 수 있는 문제

**공통 SDK 코드 자체는 이번에 수정하지 않습니다.**

기존 SDK v0.5.11이 v4를 실제로 지원한다고 단정하지 마세요.
