# 중앙 내 방식 QR — AI 실시간 화면 변환 API 1차 구현

현재 프로젝트는 중앙 **‘내 방식 QR’ Replit**입니다.

사이트: https://naebangsikqr.replit.app

이번 작업의 목표는 **기존 OpenAI Responses API를 활용하여, 키오스크의 화면 구조와 사용자의 QR 접근성 설정을 분석하고 화면 배치 계획을 생성하는 서버 API를 실제로 구현하는 것**입니다.

이전 읽기 전용 조사는 완료됐으므로 이번에는 승인된 범위 안에서 소스 구현 및 테스트를 진행하세요.

다만 **Production DB 변경, Publish, 데모커피·무인민원발급기 프로젝트 수정, 공통 SDK 수정은 금지**합니다.

## 1. 전체 개발 방향

현재 시스템은 다음 기능을 이미 갖추고 있습니다.

- 큰 글씨·큰 버튼·고대비
- 하단 조작 영역 60·70·80%
- 상단 쉬운 말 안내
- 상단 스마트 길잡이
- 아래쪽 내용 안내
- QR 프로필 적용과 세션 초기화

AI는 이 기능을 다시 구현하거나 설정을 변경하지 않습니다.

**AI는 기존 접근성 기능이 적용되는 업무 콘텐츠 영역의 배치를 결정하는 역할**을 맡습니다.

첫 시연은 데모커피의 메뉴 목록 화면부터 시작하되, AI 요청과 결과 검증의 공통 구조는 향후 메뉴 옵션, 무인민원발급기, 식당 키오스크 등으로 재사용할 수 있어야 합니다.

AI가 정해진 규칙을 실행하는 척하는 모의 기능이 아니라, 실제 OpenAI Responses API 호출을 통해 구성안을 생성할 수 있는 구조를 구현하세요.

단, 이번 작업에서는 유료 AI 실호출을 실행하지 말고 Mock 테스트로 검증하세요.

## 2. 기존 OpenAI 기능 재사용

기존 조사 내용:

- `server/recommendation.ts`의 `recommendAccessibility()`
- OpenAI Responses API
- `OPENAI_API_KEY` 서버 환경 변수
- `OPENAI_MODEL` 또는 기본 모델 설정
- 엄격한 JSON Schema 응답
- Zod 검증
- `store:false`
- 기존 추천 API의 18초 타임아웃 및 오류 처리

먼저 실제 코드를 확인하고, 기존 API 키와 OpenAI 클라이언트 설정을 재사용하세요.

**새 OpenAI API 키 발급은 필요하지 않습니다.**

기존 AI 접근성 설정 추천 기능을 수정하거나 제거하지 마세요.

새 AI 화면 변환 기능은 별도 파일·스키마·프롬프트로 분리하세요.

## 3. 신규 API 구현

중앙 서버에 다음 경로를 추가하세요.

`POST /api/ai-layout/plan`

권장 파일:

- `server/app.ts` — 라우트 및 요청 처리
- `server/ai-layout.ts` — OpenAI 호출
- `server/layout-plan.ts` — 입력·출력 스키마와 엄격한 검증
- 별도의 관련 테스트 파일

실제 프로젝트 구조에 맞춰 파일명은 조정할 수 있습니다.

이번 API는 **화면 구성 계획을 반환**할 뿐, 중앙 서버에서 키오스크의 HTML을 직접 변경하지 않습니다.

## 4. AI 입력 — 안전한 화면 구조 모델

입력 구조에는 다음 정보를 포함할 수 있도록 설계하세요.

- 화면 모델 버전
- 호스트 앱 ID
- 화면 ID
- 구조 버전 또는 해시
- 요소의 안정적인 ID
- 요소 역할 및 그룹
- 원래 순서
- 화면 크기 구간
- 고정 조작부·사용 가능한 콘텐츠 영역 정보
- 허용된 공통 배치 연산과 파라미터 범위
- QR 프로필에서 추출한 필요한 접근성 제약

**중요: 데모커피는 현재 메뉴가 이미 1열입니다.**

따라서 '기존 2열 → AI가 1열로 변경'이라는 예시를 실제 화면 구조라고 가정하지 마세요.

현재 데모커피의 구체적인 레이아웃은 후속 데모커피 연동 단계에서 실제 DOM·React 구조를 확인해 확정합니다.

이번 서버 API는 특정 호스트의 1열·2열 전환에 고정되지 않도록 설계하세요.

또한 AI 입력에 다음 항목은 포함하지 마세요.

- 사용자 입력값
- 이름, 주민등록번호, 주소, 전화번호
- QR 토큰 및 인증정보
- 주문 상태 전체
- 결제 정보
- DOM 전체 HTML 또는 무차별 추출한 textContent
- 사용자 자유 입력 텍스트
- 현재 선택한 메뉴 등 사용자별 업무 진행 상태

정적인 화면 구조와 호스트가 안전하다고 명시한 정보만 사용할 수 있어야 합니다.

## 5. 범용 배치 계획 설계

특정 키오스크의 완성된 템플릿 하나를 선택하는 방식에만 묶이지 않도록 하세요.

대신 여러 키오스크에 공통으로 적용할 수 있는 **제한된 배치 연산**을 검토하여 구조화된 계획으로 반환하도록 설계하세요.

예를 들면 다음과 같습니다.

- 콘텐츠 그룹의 세로·가로 배치
- 그룹 내부 정렬
- 허용 범위의 간격 조정
- 이미지와 텍스트의 상대적 배치
- 허용 범위의 열 개수
- 카드 내부 정보의 공간 배분

단, 실제로 적용 가능한 연산은 반드시 호스트가 해당 화면에 허용한 목록으로 제한합니다.

AI는 허용하지 않은 연산이나 값·요소를 새로 만들어서는 안 됩니다.

AI 계획에 다음의 변경을 허용하지 마세요.

- QR 사용자 설정 변경
- 쉬운 말 안내·스마트 길잡이 위치 및 타이머 변경
- 스크롤 안내 ON/OFF 변경
- 하단 조작 비율 변경
- 고정 QR 버튼·footer 이동
- 필수 버튼 삭제
- 원래 메뉴 항목 삭제 또는 상품 순서 임의 변경
- 가격·수량·업무 데이터 변경
- 클릭 동작·결제 동작 변경

기존 글씨·버튼 크기와 접근성 제약을 AI 계획보다 우선시하세요.

## 6. 구조화된 응답과 검증

OpenAI의 구조화된 JSON 응답을 사용하세요.

응답에는 다음을 포함하도록 설계하세요.

- 계획 스키마 버전
- 대상 화면 ID
- 요청 당시 구조 버전·해시
- 허용된 배치 연산의 배열 또는 제한된 구성
- 대상 요소·그룹 ID
- 허용된 파라미터
- 제한된 판단 이유 코드

AI가 HTML·CSS 원문·JavaScript를 생성해 실행하는 구조는 금지합니다.

Zod의 엄격한 검증을 사용하고 다음을 거부하세요.

- 알 수 없는 필드
- 등록되지 않은 호스트·화면·요소 ID
- 허용하지 않은 연산
- 파라미터 범위 초과
- 화면 구조 불일치
- 변경할 수 없는 영역 참조
- 필수 업무 요소를 누락시키는 계획

특히 **요청자가 보낸 허용 목록을 그대로 신뢰해서는 안 됩니다.**

중앙 서버에서 신뢰할 수 있는 호스트·화면별 허용 정책을 확인하고 검증하는 구조가 필요합니다.

현재 데모커피의 실제 레이아웃 계약이 확정되지 않았다면 임의로 만들어 확정하지 말고, 범용 스키마와 초기 검증 가능한 정책만 구현한 뒤 남은 계약 항목을 보고하세요.

서버에서 검증했다고 해서 실제 화면에 안전하다는 것이 보장되지는 않으므로, 향후 호스트에서도 별도의 화면·배치 검증이 가능해야 합니다.

## 7. 서버 간 인증 및 비용 제한

요청 흐름은 다음을 목표로 합니다.

데모커피 브라우저 → 데모커피 서버 → 중앙 QR 서버 → OpenAI

중앙 서버의 새 API는 **브라우저에서 인증 없이 공개 호출할 수 없도록** 하세요.

- 호스트 서버 간 비밀 인증 토큰 적용
- 토큰은 환경 변수 또는 Replit Secrets에서 읽기
- 코드에 비밀값 직접 작성 금지
- OpenAI API 키와 호스트 인증 토큰 분리
- 개발·운영 인증값 분리 가능하도록 설계
- 인증 실패 시 AI 호출 전 차단
- 호스트별 요청 제한
- 요청 본문 크기 및 요소 개수 제한
- 타임아웃 및 출력 토큰 상한
- 동일 요청의 불필요한 중복 방지

인증 비밀값이 아직 없다면 **실제 값을 만들어 코드에 고정하지 말고**, 필요한 환경 변수 이름과 설정 방법을 최종 보고하세요.

비밀값이 없는 상태에서 개발 API를 공개적으로 열거나 인증을 우회하지 마세요.

실제 운영에서는 여러 서버 인스턴스 사이에 요청량 제한 상태를 공유할 수 있어야 합니다. 첫 구현의 제한이 메모리 기반이라면 전역 비용 상한을 보장하지 못한다는 점을 명시하고 운영 배포 전 해결 필요사항으로 보고하세요.

## 8. AI 실패 시 안전 동작

AI 화면 변환 API가 실패하더라도 기존 키오스크 기능은 계속 작동해야 합니다.

다음 상황을 처리하세요.

- 모델 응답 지연
- 타임아웃
- 인증 실패
- OpenAI 오류
- 응답 형식 오류
- 알 수 없는 배치 연산
- 현재 화면과 다른 구조 해시
- 허용 범위를 벗어난 파라미터

서버는 오류를 안전한 상태 코드와 일반화된 오류 형식으로 반환해야 합니다.

OpenAI 오류 원문이나 요청·응답의 민감한 내용을 노출하지 마세요.

이번에는 서버 API까지만 구현하므로, **실제 화면 원복은 후속 데모커피·SDK 작업에서 수행한다는 점을 구분**하세요.

## 9. 테스트 범위

실제 OpenAI 유료 호출 없이 Mock으로 다음을 확인하세요.

1. 정상적인 화면 모델 검증
2. 허용된 배치 계획 반환
3. 지원하지 않는 화면·호스트 거부
4. 알 수 없는 연산·요소 ID 거부
5. 허용 범위 밖 파라미터 거부
6. 잘못된 타입과 추가 필드 거부
7. 개인정보·QR 토큰을 포함한 예상 외 요청 필드 거부
8. 인증 누락·오류 차단
9. OpenAI 오류·타임아웃 시 안전한 응답
10. 응답의 화면 ID·구조 해시 일치 확인
11. 기존 AI 설정 추천 기능 유지
12. QR v5 프로필 처리 기능 유지
13. 타입 검사·서버 테스트·빌드

테스트에서 유료 AI 호출이 발생하지 않도록 Mock이 실제로 적용됐는지 확인하세요.

DB 통합 테스트가 운영 DB에 접근하거나 데이터를 생성할 가능성이 있다면 안전성이 확인되기 전에는 실행하지 마세요.
