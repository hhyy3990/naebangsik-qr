# 내 방식 QR — 실제 QR 통합 테스트 준비 및 연결 상태 점검

현재 프로젝트는 **중앙 내 방식 QR Replit**입니다.

이번 작업의 목적은 실제 QR을 생성하고, 데모커피와 무인민원발급기에서 접근성 설정을 직접 적용해 볼 수 있도록 기존 연결 상태를 확인하고 테스트를 준비하는 것입니다.

사용자는 SDK를 반복 수정하기보다 실제 QR을 사용해 다양한 접근성 설정을 직접 확인한 뒤 발견된 문제만 수정하기를 원합니다.

**새로운 기능이나 동작 방식을 임의로 추가하지 마세요. 수정이 필요하면 먼저 원인과 변경 범위를 보고하고 사용자 승인을 기다려 주세요.**

## 1. 현재 중앙 QR 서비스 상태 조사

먼저 다음을 확인하세요.

- 현재 Development와 Production의 서비스 URL
- Development의 QR 프로필 스키마 버전
- Production의 QR 프로필 스키마 버전
- v1~v4 프로필 지원 상태
- 기존 QR 생성·조회·수정·폐기·재발급 흐름
- 실제 QR 조회 API 경로 및 응답 구조
- Development와 Production 데이터베이스 구분
- QR 토큰 유효성 검증
- QR 조회 시 캐시 정책
- QR 링크와 키오스크 조회 방식

Production에는 기존 사용자가 생성한 QR이 있으므로 데이터 변경·삭제·마이그레이션을 실행하지 마세요.

## 2. 실제 QR 연결 가능 여부 확인

현재 다음 두 키오스크가 중앙 QR 조회 API와 실제로 연결될 수 있는지 조사하세요.

- 데모커피: SDK v0.5.27
- 무인민원발급기: SDK v0.5.27

두 키오스크는 각자 별도의 Replit 프로젝트입니다.

현재까지 키오스크에서 QR v1~v4 프로필을 적용한 테스트는 주로 브라우저의 모의 API 응답으로 이루어졌습니다.

이번에는 실제 중앙 QR 서비스의 저장된 프로필을 키오스크가 조회할 수 있는지 확인해야 합니다.

조사 항목:

- 현재 키오스크 SDK가 사용하는 QR 조회 엔드포인트
- 실제 중앙 서비스의 조회 API
- 두 API의 경로·응답 구조 일치 여부
- HTTPS 접근 가능 여부
- 브라우저 CORS 정책
- 인증이나 토큰 검증 조건
- Development Preview 외부 접근 가능 여부
- 기존 Production QR 조회와의 호환성
- v4 프로필 설정이 누락 없이 전달될 수 있는지

중앙 프로젝트에서 확인할 수 없는 키오스크 내부 설정은 추측하지 말고, 각 키오스크 Replit에서 추가 확인해야 할 항목으로 정리하세요.

## 3. Development에서 실제 QR 생성·조회 확인

운영 DB와 분리된 Development 데이터베이스만 사용합니다.

현재 구현된 정상적인 QR 생성 흐름으로 테스트 프로필을 생성하고 실제 조회 API가 저장된 설정을 반환하는지 확인하세요.

우선 다음 두 가지 프로필을 사용합니다.

### 테스트 A — 일반 화면

- 하단 조작 사용하지 않음
- 매우 큰 글씨
- 큰 버튼
- 고대비
- 쉬운 말 활성화
- 스마트 길잡이 활성화

### 테스트 B — 하단 조작 80%

- 하단 조작 80%
- 매우 큰 글씨
- 큰 버튼
- 고대비
- 쉬운 말 활성화
- 스마트 길잡이 활성화

그 외 설정은 현재 지원하는 기본값을 유지합니다.

기존 QR 프로필 구조에 있는 설정만 사용하고 새로운 옵션을 만들지 마세요.

이 두 프로필을 기준으로 실제 QR 생성 → API 조회 → 응답 설정 일치 여부를 확인하세요.

QR 토큰이나 관리 권한 정보는 로그에 불필요하게 출력하지 마세요.

각 키오스크 Replit에서 실제 QR을 적용할 수 있도록 다음 정보를 정리하세요.

1. 중앙 QR Development 접근 URL
2. 실제 QR 조회 엔드포인트
3. QR 프로필 v4 응답 예시 구조
4. 테스트 QR을 생성하고 조회하는 방법
5. 기존 QR 스캔·입력 경로와의 연결 방법
6. Development와 Production API의 차이
7. CORS·캐시·토큰 유효성 관련 주의사항
8. QR 조회 실패 시 기존 오류 처리 경로
9. 중앙 API와 키오스크 SDK 간 추가 연결 작업이 필요한지

실제 테스트 QR을 생성했다면 사용자가 직접 열거나 확인할 수 있는 기존 UI 경로도 알려 주세요.

## 5. 실제 QR 적용 후 확인할 접근성 설정

다음 항목을 사용자가 직접 비교할 예정입니다.

- 하단 조작 없음 / 60% / 70% / 80%
- 글씨 기본 / 크게 / 매우 크게
- 버튼 기본 / 크게
- 고대비 켜기 / 끄기
- 쉬운 말 켜기 / 끄기
- 스마트 길잡이 켜기 / 끄기
- 기존 v4의 나머지 지원 설정

특히 일반 화면에서 쉬운 말 안내가 업무 콘텐츠 위에 표시되면서 중요한 내용이나 버튼을 가리는지 확인해야 합니다.

**이번 단계에서는 레이아웃을 임의로 변경하지 마세요.**

실제 QR 적용 이후 문제를 관찰하고 수정 여부를 결정합니다.

## 6. 기존 미해결 오류 기록

무인민원발급기 SDK v0.5.27에서는 320×844, 하단 80%, 극단적으로 긴 쉬운 말 시험 문구 사용 시 안내 본문이 약 11px 잘리는 문제가 발견됐습니다.

이 문제는 아직 해결되지 않았습니다.

이번 작업에서 새 SDK 버전을 만들거나 해당 오류를 임의로 우회하지 마세요.

실제 QR을 통한 일반적인 안내 화면에서도 같은 현상이 발생하는지 후속 검증 대상으로 기록하세요.

## 7. 작업 범위 제한

이번 작업에서 허용되는 것은 다음뿐입니다.

- 기존 중앙 QR 코드와 API 연결 상태 조사

- 기존 데이터 구조를 활용한 설정 일치 여부 확인
- 실제 키오스크 연동에 필요한 정보 정리
- 테스트 결과 보고

금지 사항:

- Production DB 변경
- Production QR 마이그레이션
- 중앙 QR Publish
- QR 스키마 변경
- 새로운 기능 추가
- 새로운 UI 추가
- AI API 변경
- SDK 수정
- 데모커피 프로젝트 수정
- 무인민원발급기 프로젝트 수정
- 기존 QR 삭제·폐기·재발급
- 사용자 승인 없는 API 구조 변경

Development 환경에서 실제 키오스크 연결을 위해 코드 변경이 필요하다면, **어느 프로젝트의 어떤 코드가 왜 변경돼야 하는지 먼저 보고하고 승인받으세요.**
