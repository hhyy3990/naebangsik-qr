# 프로젝트: 내 방식 QR (MyWay QR)

## 개발 목표

AI 라이프 솔루션 챌린지에 제출할 접근성 프로필 서비스의 첫 번째 MVP를 개발한다.

서비스명: **내 방식 QR**

슬로건: **한 번 설정하면, 어디서나 내 방식대로**

이 서비스는 장애인, 고령층 등 디지털 기기 사용에 어려움을 겪는 사용자가 자신의 선호 접근성 환경을 설정하고 QR로 저장해, 서로 다른 키오스크에서 동일한 설정을 재사용하도록 지원한다.

최종적으로 독립된 카페 키오스크와 병원 키오스크를 연동할 예정이지만, 이번 작업에서는 중앙 프로필 및 QR 서비스만 구현한다.

## 기술 스택

- React + TypeScript
- Tailwind CSS
- Node.js + Express
- PostgreSQL
- QR 생성 라이브러리
- 모바일 반응형 웹

## 구현할 화면

### 1. 메인 페이지
- 서비스명 및 슬로건 표시
- '내 QR 만들기' 버튼
- '내 QR 불러오기' 버튼
- 접근성 프로필 서비스 소개
- 큰 글씨와 명확한 버튼을 사용한 디자인

### 2. 프로필 생성 페이지

다음 접근성 설정을 사용자가 직접 선택할 수 있도록 구현한다.

- 글씨 크기: 기본 / 크게 / 아주 크게
- 버튼 크기: 기본 / 크게
- 화면 대비: 기본 / 고대비
- 쉬운 말: 사용 / 사용 안 함
- 화면 구성 단순화: 사용 / 사용 안 함
- 하단 조작 모드: 사용 / 사용 안 함
- 스마트 길잡이: 사용 / 사용 안 함
- 스마트 길잡이 안내 시작 시간: 10초 / 15초 / 20초
- 음성 안내: 사용 / 사용 안 함

사용자는 각 설정을 실시간 미리보기로 확인할 수 있어야 한다.

### 3. QR 발급 페이지
- 접근성 설정을 데이터베이스에 저장
- 암호학적으로 안전한 무작위 프로필 토큰 생성
- QR 코드 발급
- QR 이미지 저장 기능
- 설정을 확인하고 변경할 수 있는 기능
- QR 폐기 및 재발급 기능

### 4. QR 프로필 조회 기능
향후 다른 웹사이트에서 공통 API를 이용할 수 있도록 구현한다.

- POST /api/profiles : 프로필 생성
- POST /api/profiles/resolve : QR 토큰으로 설정 조회
- PATCH /api/profiles/:id : 설정 수정 (별도 관리 권한 검증 필수)
- POST /api/profiles/:id/revoke : 토큰 폐기 (별도 관리 권한 검증 필수)

QR 조회 토큰과 프로필 수정·폐기 권한은 분리한다. QR을 가진 사람에게 수정 권한을 부여하지 않는다.

키오스크에 반환하는 정보는 개인의 접근성 선호 설정으로 한정하고, 이름·장애 유형·주민등록번호·연락처는 수집하지 않는다.

### 5. 공통 접근성 규격

향후 카페와 병원 키오스크에서 동일하게 해석할 수 있도록 버전이 있는 JSON 스키마를 사용한다.

프로필은 특정 키오스크의 실제 버튼 위치가 아니라 글자 확대, 주요 조작 영역의 배치, 안내 방식 등 의미 중심의 선호 정보를 표현해야 한다.

## 디자인 요구사항

- 전체적으로 깔끔하고 현대적인 디자인
- 따뜻한 오프화이트 배경, 네이비 계열 글자, 블루 포인트
- 읽기 쉬운 한국어 고딕 폰트
- 모바일에서도 가로 스크롤이나 글자 잘림이 없도록 구성
- 화면 확대 시에도 버튼과 문구가 서로 겹치지 않아야 함
- 처음 이용하는 고령층도 이해할 수 있는 쉬운 안내 문구 사용

## 개발 원칙

1. 임시 메모리가 아닌 지속 가능한 데이터베이스에 저장한다.
2. 회원가입 없이 프로필을 만들 수 있게 한다.
3. QR 토큰은 프로필 조회용, 관리 권한은 별도 비밀값으로 구분한다.
4. 서버에 관리용 비밀값을 평문으로 저장하지 않는다.
5. 프로필 관리 기능은 관리 권한을 확인한 사용자에게만 제공한다.
6. 향후 서로 다른 Replit 프로젝트에서 API를 호출할 수 있도록 구조를 설계한다.
7. API 키와 서버 비밀값은 환경변수로 관리한다.
8. CORS는 허용된 연동 서비스 중심으로 설정할 수 있도록 구성한다.
9. 테스트용 데이터와 실제 저장 데이터를 구분한다.
10. 아직 카페·병원 키오스크나 AI 기능을 구현하지 않는다.

## 이번 단계의 완료 기준

- 사용자가 프로필을 생성할 수 있다.
- QR 코드가 정상적으로 발급된다.
- 발급한 QR 토큰으로 프로필을 조회할 수 있다.
- 브라우저를 새로고침해도 저장된 데이터가 유지된다.
- QR을 폐기한 후에는 기존 토큰으로 프로필을 조회할 수 없다.
- 모바일 화면에서도 정상적으로 사용할 수 있다.
- 기본 API 테스트와 타입 검사가 통과한다.

구현이 끝나면 생성된 파일 구조와 테스트 결과를 설명해줘.
