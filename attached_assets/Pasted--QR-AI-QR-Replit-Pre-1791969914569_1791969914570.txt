# 내 방식 QR — AI 추천 결과 화면 이동 오류·추천 이유 중복·글씨 크기 추천 수정

현재 작업 대상은 중앙 **내 방식 QR** Replit 프로젝트입니다.

실제 Preview에서 사용자가 직접 확인한 문제 세 가지를 수정해 주세요.

이번 작업은 새로운 기능 개발이 아니라 **이미 구현한 AI 추천 기능의 UI 흐름과 추천 정확도를 보완하는 작업**입니다.

기존 QR v3, OpenAI API 연결, QR 생성·저장·관리 기능은 유지하세요.

## 1. AI 추천 완료 후 일반 설정 화면이 먼저 보이는 문제

### 현재 실제 현상

사용자가 다음 순서로 진행했습니다.

1. 홈에서 AI 추천받기 선택
2. 질문에서 불편함 선택
3. '내 설정 추천받기' 클릭
4. AI 추천 성공
5. 그러나 화면이 기존 일반 설정 영역으로 이동함

추천 결과 카드인 **'나에게 맞는 설정을 준비했어요'**는 존재하지만, 사용자가 기대한 위치에 바로 표시되지 않습니다.

이전에 수정했다고 보고했으나 실제 사용자 브라우저에서 문제가 재현됐습니다.

### 반드시 수정할 동작

'내 설정 추천받기'를 누르고 AI 응답 검증이 성공하면 다음 순서로 동작해야 합니다.

1. AI 추천값을 기존 설정 상태에 즉시 자동 반영
2. 추천 결과 카드 표시
3. **추천 결과 카드의 제목이 현재 브라우저 화면에 보이도록 정확히 스크롤 또는 화면 전환**
4. 기존 상세 설정 영역은 결과 확인 전에는 화면에 먼저 나타나지 않도록 처리
5. 사용자가 '이 설정 사용하기'를 누르면 그때 기존 설정 편집 영역으로 이동

**추천값이 내부 상태에 자동 반영되는 시점과 상세 설정 화면으로 이동하는 시점은 구분하세요.**

추천값은 AI 응답 성공 즉시 적용되어야 하지만, 사용자가 보는 화면은 결과 카드여야 합니다.

### 기술적 진단 요청

단순히 기존 스크롤 함수를 한 번 더 호출하는 식으로 추측해서 수정하지 마세요.

현재 코드에서 다음을 확인하세요.

- 추천 응답 성공 후 호출되는 모든 스크롤 함수
- 부모 컴포넌트의 설정 상태 변경으로 실행되는 useEffect
- AI 결과 표시 상태 및 결과 카드 렌더링 타이밍
- `scrollIntoView`, `window.scrollTo`, hash navigation 등 기존 이동 로직
- 설정 상태 변경 이후 실행되는 자동 포커스
- 모바일 브라우저에서 결과 카드보다 상세 설정 영역이 먼저 보이는 원인
- 비동기 렌더링 이후 스크롤 위치가 덮어써지는 경쟁 상태

필요하다면 결과 화면을 명시적인 UI 단계로 관리하여 AI 추천 성공 시 결과 화면이 최우선으로 표시되도록 하세요.

결과 카드가 렌더링된 후 실제 위치를 기준으로 이동해야 합니다.

가능하면 'AI 추천 결과' 단계에서는 기존 상세 설정 편집 영역을 잠시 숨기고, '이 설정 사용하기'를 눌렀을 때 상세 설정 영역을 표시하는 구조를 우선 검토하세요.

단, 이미 반영된 설정 상태 자체는 잃지 않아야 합니다.

### 성공 기준

AI 추천이 완료되면 모바일과 데스크톱 모두에서 다음 내용이 먼저 보여야 합니다.

**나에게 맞는 설정을 준비했어요**

그 아래 추천 이유와 **이 설정 사용하기** 버튼이 보여야 합니다.

사용자가 다시 스크롤해 결과 카드를 찾아야 하는 것은 실패입니다.

## 2. 추천 이유 중복 표시 제거

### 현재 문제

실제 Preview에서는 AI 추천 이유가 두 군데에 표시됩니다.

- 첫 번째: '나에게 맞는 설정을 준비했어요' 결과 카드의 추천 이유 목록
- 두 번째: 상세 설정 화면의 '음성 안내' 아래쪽에 나타나는 파란색 AI 추천 이유 박스

이렇게 같은 내용이 반복되면 화면이 불필요하게 길어지고 복잡해집니다.

### 수정 요청

**AI 추천 이유는 추천 결과 카드 한 곳에만 표시하세요.**

상세 설정 영역에 중복으로 나타나는 파란색 추천 이유 박스는 제거합니다.

다음 기능은 유지합니다.

- AI 추천 이유 데이터 자체
- 결과 카드의 2~4개 추천 이유
- 추천 결과를 기존 설정 상태에 자동 반영
- 직접 설정 수정 가능
- QR 저장·생성 기능

상세 설정 화면은 글씨 크기, 버튼 크기, 고대비, 쉬운 말, 스마트 길잡이 등 **실제 설정을 확인하고 수정하는 기능에 집중**하게 해 주세요.

## 3. 작은 글씨가 불편한 80대 이상 사용자에게 '매우 크게' 우선 추천

### 현재 문제

사용자가 다음을 선택했습니다.

- 연령대: 80대 이상
- 불편함: 작은 글씨가 잘 안 보여요

그런데 AI가 `textSize: large`를 추천했습니다.

이 경우는 사용자가 실제로 글씨를 보기 어렵다고 밝혔으므로 **'매우 크게(extraLarge)'를 우선 추천하는 것이 더 적절**합니다.

### 요구사항

AI 추천 기준에 다음 구체적 사례를 반영하세요.

**80대 이상 + '작은 글씨가 잘 안 보여요' 선택 → `textSize: extraLarge` 우선 추천**

이 규칙은 나이만으로 기능을 결정하라는 뜻이 아닙니다.

- 연령대만 80대 이상이고 글씨 불편을 선택하지 않았다면 자동으로 매우 크게를 강제하지 않습니다.
- 다른 연령대라도 작은 글씨가 매우 불편하다는 자유 입력이 있으면 매우 크게를 추천할 수 있습니다.
- 사용자가 '큰 글씨는 오히려 불편하다' 등의 상충하는 선호를 직접 작성하면 그 내용을 고려하고, 필요하면 선택 이유나 확인 안내에 반영합니다.
- AI 모델 프롬프트에 이 사례와 추천 기준을 명시합니다.
- 사용자가 추천값을 나중에 '크게' 또는 '기본'으로 변경할 수 있어야 합니다.

모델 프롬프트만 바꾸는 것으로 그치지 말고, 이 사례를 포함하는 회귀 테스트를 추가해 실제 추천 동작의 일관성을 확인하세요.

현재 QR v3의 정확한 값 `extraLarge`를 사용해야 합니다. 새로운 글씨 크기 enum은 만들지 마세요.

### 추천 이유 예시

**작은 글씨를 읽기 어렵다고 하셔서 글씨를 매우 크게 설정했어요. 미리보기에서 편한 크기인지 확인해 보세요.**

결과 카드에는 실제 적용된 `textSize`와 일치하는 표현이 나와야 합니다.

'매우 크게'가 적용됐는데 설명은 '크게'라고만 하는 등 불일치가 발생하지 않도록 검증하세요.

## 4. 결과 화면과 이동 버튼 유지

추천 결과 카드는 기존 구성을 유지합니다.

- 제목: 나에게 맞는 설정을 준비했어요
- 설명: 이런 점을 생각해 추천했어요.
- 추천 이유: 2~4개
- 안내: 적용한 뒤에도 설정을 직접 바꿀 수 있어요.
- 주요 버튼: 이 설정 사용하기
- 보조 버튼: 답변 다시 보기 / 직접 설정하기

### 버튼 동작

**이 설정 사용하기**
- AI가 이미 반영한 설정을 유지
- 상세 설정 화면으로 이동
- 미리보기도 동일한 설정 표시

**답변 다시 보기**
- 이전 질문 응답 유지
- AI 질문 화면으로 이동

**직접 설정하기**
- 기존 상세 설정 화면으로 이동
- 현재 적용된 설정을 의도치 않게 초기화하지 않음

AI 추천 오류·타임아웃 시 기존 설정을 변경하지 마세요.

## 5. 실제 브라우저 검증 필수

이번에는 이전과 달리 실제 사용자 화면에서 문제가 재현됐으므로, **코드만 검사하고 정상이라고 보고하지 마세요.**

가능한 브라우저 자동화 도구를 사용해 실제 클릭·스크롤·설정값을 검증하세요.

테스트 화면 크기:

- 320×844
- 360×667
- 390×844
- 1440×900

### 필수 시나리오 A: 추천 결과 첫 표시

1. 홈페이지 진입
2. AI 추천받기 클릭
3. 연령대 80대 이상 선택
4. 작은 글씨가 잘 안 보여요 선택
5. 내 설정 추천받기 클릭
6. 실제 AI 추천 응답 확인
7. 추천 결과 화면이 맨 먼저 보이는지 확인

이때 브라우저가 상세 설정의 중간이나 아래쪽에 머물면 실패입니다.

### 필수 시나리오 B: 글씨 크기 추천

같은 입력에서 `textSize: extraLarge`가 실제 추천되고, 기존 설정 상태에 적용되는지 확인합니다.

결과 이유가 실제 설정과 일치하는지 확인합니다.

### 필수 시나리오 C: 이유 중복 제거

추천 결과 카드에는 추천 이유가 나타나고, 상세 설정의 아래쪽 파란색 AI 추천 이유 박스는 없어야 합니다.

### 필수 시나리오 D: 설정 이동 및 저장

1. 이 설정 사용하기 클릭
2. 상세 설정 화면 이동
3. 글씨 크기 '매우 크게' 선택 상태 확인
4. 사용자가 '크게'로 직접 변경
5. 기존 저장 버튼 클릭
6. Development QR 생성·조회로 최종 설정 확인

테스트 프로필은 별도로 식별하고 정리합니다.

사용자의 기존 QR과 운영 DB 데이터는 건드리지 마세요.
