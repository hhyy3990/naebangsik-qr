# 중앙 ‘내 방식 QR’ — 데모커피 AI 화면 계약 v2 등록 및 서버 정책 검증

현재 프로젝트는 중앙 **‘내 방식 QR’ Replit**입니다.

서비스 주소: https://naebangsikqr.replit.app

이번 작업의 목표는 이미 구현한 `POST /api/ai-layout/plan`에 **데모커피 메뉴 화면의 실제 레이아웃 계약 v2를 등록하고, 중앙 서버가 올바른 AI 화면 변환 계획만 허용하도록 검증하는 것**입니다.

이번에는 중앙 서버의 정책·스키마·검증 코드만 필요한 범위에서 수정합니다.

**데모커피 프로젝트, 공통 SDK, Production DB, Publish는 변경하지 마세요. 실제 OpenAI 유료 호출도 하지 마세요.**

## 1. 현재 상태

중앙 서버에는 다음이 구현돼 있습니다.

- `POST /api/ai-layout/plan`
- OpenAI Responses API 호출 모듈
- 엄격한 JSON Schema 및 Zod 검증
- 서버 간 Bearer 인증
- 요청 제한 및 동일 요청 중복 억제
- AI 실패 시 일반화된 오류 응답
- `store:false`
- DB 저장 없는 무상태 화면 계획 API

관련 파일:

- `server/app.ts`
- `server/ai-layout.ts`
- `server/layout-plan.ts`
- `server/layout-policies.ts`
- `server/ai-layout.test.ts`

현재 실제 호스트 정책이 비어 있어서 AI 화면 계획 API는 의도적으로 비활성화된 상태입니다.

이번에는 데모커피 메뉴 화면 정책 하나만 등록합니다.

## 2. 데모커피가 실제 구현한 화면 계약 v2

다음 값은 데모커피 Replit Agent의 구현·브라우저 검증 결과입니다.

| 항목 | 값 |
|---|---|
| 호스트 ID | `democoffee` |
| 화면 ID | `cafe.menu` |
| 화면 모델 `schemaVersion` | `2` |
| 구조 버전 | `menu.v2` |
| 구조 해시 | `837f86b3` |
| 화면 너비 380px 이하 | `compact` |
| 화면 너비 380px 초과 | `regular` |
| 360px 표준 설정 제약 해시 | `207c8de6` |
| 390px 표준 설정 제약 해시 | `df5bb9a5` |

**주의:** 제약 해시는 QR 접근성 설정과 화면 조건에 따라 달라질 수 있습니다.

위 두 제약 해시를 모든 프로필에 적용되는 고정값으로 취급하지 마세요.

구조 해시는 현재 데모커피의 `menu.v2` 계약을 기준으로 생성된 값입니다. 해시 알고리즘은 32비트 FNV-1a입니다.

중앙 서버가 별도 해시 생성 규칙을 갖고 있다면 값을 임의로 대체하지 말고, 실제 계약을 대조해 정확히 호환되도록 처리하세요.

## 3. 화면 요소 및 보호 영역 등록

데모커피의 실제 모델에는 다음 의미 ID가 있습니다.

### 콘텐츠 그룹

- `menu.product-card`
- `menu.product-image`
- `menu.product-information`
- `menu.product-name`
- `menu.product-price`
- `menu.product-description`
- `menu.product-action`

### 메뉴 및 고정 영역

- `menu.product-list`
- `menu.category-navigation`
- `menu.fixed-controls`

그룹 관계:

- `menu.product-card`
  - `menu.product-image`
  - `menu.product-information`

- `menu.product-information`
  - `menu.product-name`
  - `menu.product-price`
  - `menu.product-description`
  - `menu.product-action`

필수 보존 ID:

- `menu.category-navigation`
- `menu.product-list`
- `menu.fixed-controls`
- `menu.product-action`

보호 원칙:

- 모든 메뉴 항목 유지
- 메뉴 표시 순서 유지
- 카테고리 유지
- 상품명·가격·설명 유지
- 기존 선택 이벤트 유지
- QR 도크와 고정 조작부 유지

`menu.product-list`는 전체 삭제·재정렬이 금지된 보호 영역이지만, **명시적으로 허용된 `setGroupColumns` 연산을 통한 열 개수 변경만 예외적으로 허용**합니다.

AI가 보호 영역 전체를 자유롭게 조작할 수 있도록 해석하면 안 됩니다.

## 4. 허용된 AI 배치 연산 세 가지

현재 데모커피에서 구현된 연산은 다음과 같습니다.

### A. `setGroupColumns`

대상:

`menu.product-list`

의미:

메뉴 목록의 열 개수 변경.

후보 값:

- `columns: 1`
- `columns: 2`

다만 실제 허용 여부는 뷰포트와 접근성 제약에 따라 결정해야 합니다.

- `compact`에서는 2열을 허용하지 않습니다.
- 큰 글씨·큰 버튼 조합 등 데모커피에서 안전하지 않다고 판단한 조건에서는 2열을 허용하지 않습니다.
- QR 설정의 접근성 제약이 열 개수 선택보다 우선합니다.

### B. `setGroupFlow`

대상:

`menu.product-card`

허용값:

- `direction: "row"`
- `gapPx`: 8~20

### C. `setChildBasis`

대상:

`menu.product-image`

허용값:

- `basisPercent`: 20~30
- `minPx`: 72~96

**중요: 위 값은 이전 데모커피 계약에서 확인한 범위와 v2 보고를 종합한 것입니다.**

실제 v2 코드의 검증 범위가 달라졌다면, 추측해서 등록하지 말고 확인된 범위만 반영하고 차이를 보고하세요.

또한 `setGroupColumns`와 카드 내부 연산은 **독립적**이어야 합니다.

열 개수만 변경하는 유효한 계획에서는 카드 내부 배치가 AI 계획 없이 강제로 변경되어서는 안 됩니다.

반대로 카드 내부 배치만 변경하는 유효한 계획에서 메뉴 열 개수를 AI가 임의로 바꿔서는 안 됩니다.

세 연산이 항상 한꺼번에 존재해야 한다고 가정하지 마세요. 데모커피 v2가 허용하는 조합과 순서만 등록하세요.

## 5. 중앙 서버 스키마와 데모커피 계약 대조

중앙 서버의 실제 입력·출력 스키마를 먼저 확인하세요.

특히 다음 필드를 비교하세요.

- `schemaVersion`
- `hostId`
- `screenId`
- `structureVersion`
- `structureHash`
- `constraintHash`
- `viewportClass`
- `groups`
- `requiredIds`
- `allowedOperations`
- `constraints`
- `operations`

중앙 서버가 요구하는 형식과 데모커피 v2 모델이 서로 다르다면, **서버 내부의 안전한 정규화·매핑으로 해결할 수 있는지 먼저 확인**하세요.

단, 값이 다른데 검증을 생략하거나 임의로 통과시키면 안 됩니다.

또한 아직 데모커피 실제 요청을 중앙 API로 보낸 적은 없으므로, **두 프로젝트 간 실제 네트워크 호환성이 확인됐다고 보고하지 마세요.**

계약을 정확히 일치시키기 위해 데모커피 쪽 수정이 반드시 필요한 경우에는 중앙 서버만 억지로 수정하지 말고 차이점과 후속 작업을 보고하세요.

## 6. QR 접근성 설정 제약 검증

데모커피 화면 모델에서 현재 확인된 제약은 다음과 같습니다.

- `textScale`: `standard`, `large`, `extraLarge`
- `buttonScale`: `standard`, `large`
- `highContrast`: boolean
- `viewportModePercent`: `null`, 60, 70, 80
- `minimumTouchTargetPx`: 44
- `preserveTopGuidance`: `true`
- `preserveFixedControls`: `true`

제약 해시는 이러한 실제 제약 및 화면 크기 조건에 맞춰 검증해야 합니다.

QR 프로필 전체를 AI로 전달하지 마세요.

특히 다음은 AI 서버 입력에서 제외하세요.

- QR 토큰
- 개인정보
- 실제 주문 내용
- 메뉴 선택 상태
- 결제 정보
- 사용자 입력값
- DOM 전체 HTML
- 사용자 자유 입력 문구

AI가 사용자의 QR 설정을 변경하는 계획을 생성할 수 없도록 해야 합니다.

기존 SDK가 관리하는 쉬운 말 안내·스마트 길잡이·하단 조작모드·스크롤 안내·QR 도크·footer도 보호 대상입니다.

## 7. 서버 정책 등록

`server/layout-policies.ts`에 데모커피 `cafe.menu`의 신뢰할 수 있는 정책을 등록하세요.

다음 사항은 서버가 직접 검증해야 합니다.

- 등록된 호스트만 허용
- 등록된 화면만 허용
- 지원하는 화면 모델 버전만 허용
- 구조 버전·구조 해시 일치
- 그룹 및 요소 ID 일치
- 필수 요소 누락 거부
- 허용 연산만 승인
- 연산 대상 ID 일치
- 파라미터 범위 검증
- 허용하지 않은 연산 조합 거부
- 접근성 제약과 충돌하는 레이아웃 거부

요청자가 보낸 `allowedOperations`를 그대로 신뢰해 모든 연산을 허용하지 마세요.

**중앙 서버에 등록된 정책을 최종 허용 기준으로 사용**하세요.

정책이 확정되지 않은 다른 화면이나 호스트는 계속 거부해야 합니다.

## 8. AI 응답 검증

실제 OpenAI 호출은 아직 하지 않습니다.

Mock AI 응답을 사용하여 다음을 검증하세요.

정상 계획:

- 390px 일반 설정에서 1열 계획 허용
- 카드 내부 가로 배치 허용
- 이미지 비율·최소 폭 허용 범위 검증
- 독립적인 연산 적용 허용

거부 계획:

- 360px `compact`에서 2열
- 접근성 제약과 충돌하는 2열
- 허용하지 않은 요소 ID
- 허용하지 않은 연산
- 다른 화면의 구조 해시
- 제약 해시 불일치
- 범위를 벗어난 숫자
- 메뉴 항목 삭제·순서 변경
- 고정 컨트롤 또는 안내 영역 변경
- 알 수 없는 필드 추가

중앙 서버가 허용한 계획이 데모커피의 `validateMenuLayoutPlan()`에서도 허용될 수 있도록 계약이 동일해야 합니다.

단, 이번에는 데모커피 프로젝트를 직접 수정하거나 호출할 수 없으므로 **중앙 단독 Mock 검증과 실제 호스트 검증을 구분**해 보고하세요.
