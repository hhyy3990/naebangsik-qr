# 내 방식 QR — 중앙 서비스 Production v3 배포 전 안전 점검 (읽기 전용)

현재 이 프로젝트는 접근성 프로필을 생성·관리하고 QR로 저장하는 중앙 서비스 **‘내 방식 QR’**입니다.

데모커피와 무인민원발급기는 공통 접근성 SDK v0.5.5를 적용했으며, QR v3 프로필에 대한 모의 응답 테스트를 통과했습니다.

이제 중앙 서비스에서 실제 v3 QR 프로필을 발급하고 두 키오스크에 적용하기 위해 Production 배포를 준비하려고 합니다.

**이번 작업은 배포 전 안전 점검만 진행합니다. DB 변경, 데이터 수정, Publish는 절대 하지 마세요.**

---

## 1. 현재 프로젝트와 환경 확인

먼저 현재 워크스페이스가 중앙 ‘내 방식 QR’ 프로젝트인지 확인해 주세요.

다음 사항을 조사합니다.

- Development 환경의 코드와 실행 상태
- 현재 Production 배포의 버전과 상태
- Development와 Production이 각각 사용하는 DB
- 실제 Production 서비스 URL
- Production DB에 안전하게 읽기 전용으로 접근 가능한지
- 서버·클라이언트·DB 관련 설정 파일
- v3 구현이 포함된 코드 및 마이그레이션 파일

다른 프로젝트에 접속해 있다면 작업을 진행하지 말고 보고해 주세요.

환경변수의 실제 비밀값이나 DB 접속 정보는 출력하지 마세요.

## 2. Development v3 구현 상태 확인

Development에 구현된 프로필 v3 구조를 확인합니다.

핵심 설정:

- textSize: standard / large / extraLarge
- buttonSize: standard / large
- contrast: standard / high
- easyLanguage: boolean
- smartGuide: boolean
- guideDelaySeconds: 10 / 15 / 20
- voiceGuidance: boolean
- viewportMode: null 또는 { mode: "bottom", heightPercent: 60 / 70 / 80 }

다음 사항도 확인합니다.

- 새 프로필은 schemaVersion 3으로 생성
- 저장된 v3 프로필을 정상 조회
- v3 프로필 수정·폐기·재발급
- 관리 권한 없이 프로필 수정·폐기 불가
- v1/v2 프로필 조회 시 viewportMode:null로 정규화
- v1/v2 기존 데이터 자체는 불필요하게 변경하지 않음
- 새 요청에서 기존 bottomControls 및 simplifiedLayout이 허용되지 않음
- 프런트엔드의 60·70·80% 설정과 미리보기 일치
- 생성 QR에 포함된 토큰 및 URL 구조 유지

실제 코드와 테스트를 확인해 구현된 기능과 미구현 기능을 구분해 주세요.

## 3. Production 현재 스키마 확인 — 읽기 전용

Production DB에 접근할 수 있다면 다음 항목을 읽기 전용 SQL로 확인합니다.

- profiles 테이블 존재 여부
- schema_version 컬럼의 현재 기본값
- schema_version 허용 CHECK 제약 조건
- schema_version별 행 개수
- 전체 프로필 행 개수
- JSON preferences 저장 구조
- 기존 데이터의 null 값 여부
- 기타 v3와 충돌할 수 있는 제약 조건
- 관련 인덱스와 유니크 제약
- 프로필 수정·폐기·재발급에 필요한 컬럼

가능한 경우 PostgreSQL의 information_schema와 pg_catalog를 활용합니다.

**SELECT 및 읽기 전용 메타데이터 조회만 허용합니다.**

ALTER, UPDATE, DELETE, INSERT, TRUNCATE, DROP, CREATE 등은 실행하지 마세요.

실제 QR 토큰, 사용자 식별 정보, 관리용 비밀키를 보고서에 출력하지 마세요.

Production DB 접근이 불가능하면 추정값을 작성하지 말고 확인 불가로 보고합니다.

## 4. 기존 v1/v2 프로필 호환성

기존 Production DB에 저장된 v1/v2 프로필을 v3 서버에서 조회할 때 어떤 결과가 나오는지 확인합니다.

- v1 조회 시 viewportMode:null
- v2 조회 시 viewportMode:null
- 기존 bottomControls:true가 새로운 하단 조작 모드를 임의로 켜지 않음
- 기존 simplifiedLayout이 신규 화면 기능으로 되살아나지 않음
- 기존 QR 토큰의 조회 가능성 유지
- 기존 프로필 저장값은 별도 수정 전까지 보존

가능한 범위에서 Development의 테스트 DB나 fixture로 검증합니다.

Production 데이터에 쓰기 작업을 하지 마세요.

## 5. Production DB 마이그레이션 계획 검토

기존에 검토한 v3 마이그레이션 초안은 다음과 같습니다.

```sql
ALTER TABLE "profiles"
  DROP CONSTRAINT "profiles_schema_version_v2_check";

ALTER TABLE "profiles"
  ALTER COLUMN "schema_version" SET DEFAULT 3;

ALTER TABLE "profiles"
  ADD CONSTRAINT "profiles_schema_version_v3_check"
  CHECK (schema_version = ANY (ARRAY[1, 2, 3]));
```

이 SQL은 현재 Production DB의 실제 스키마와 일치하는지 확인하기 위한 **참고 초안**입니다.

이번에는 실행하지 마세요.

다음을 검토해 주세요.

- 기존 CHECK 제약 이름이 정확한지
- v1/v2 데이터가 새 제약을 통과하는지
- v3 기본값이 실제 코드와 일치하는지
- 관련 컬럼 변경이 추가로 필요한지
- 여러 마이그레이션 중복 실행 위험
- ALTER TABLE의 잠금 영향
- 적용 실패 시 트랜잭션 롤백 가능성
- Production 런타임과 DB 버전 불일치 위험
- 배포 순서와 일시적인 호환성 문제

필요하면 현재 스키마에 맞춘 **실행 전 검토용 마이그레이션 SQL**을 작성할 수 있습니다.

하지만 절대 실행하지 마세요.

## 6. 백업과 복원 가능성 확인

Production DB에 대해 다음 사항을 확인합니다.

- Replit에서 제공하는 백업 또는 스냅샷 방법
- 현재 백업이 존재하는지
- 백업 생성 권한 및 절차
- 백업에 프로필·토큰·관리 권한 데이터가 포함되는지
- 복원 절차
- DB 백업과 코드 배포 롤백의 차이
- 백업의 실제 복원 가능성을 확인할 방법

**이번에는 백업 생성 또는 복원도 임의로 실행하지 마세요.**

백업이 확인되지 않거나 복원 방법이 불명확하다면 Production 변경을 진행할 수 없는 상태라고 보고해 주세요.

## 7. 실제 QR 발급·조회 API 점검

중앙 서비스에서 SDK 소비자에게 제공하는 API를 확인합니다.

특히 다음을 점검합니다.

- 프로필 생성 API
- 프로필 조회 또는 resolve API
- QR URL 생성 방식
- QR 토큰 유효성 검사
- 프로필 수정·폐기·재발급 API
- SDK 호스트가 호출하는 서버 프록시 경로
- 응답의 preferences 구조
- v3 viewportMode 필드 반환
- 유효하지 않은 토큰의 오류 처리
- 폐기된 토큰의 조회 차단

프로필 조회 응답이 SDK v0.5.5가 기대하는 형식과 일치하는지 확인합니다.

가능하면 실제 서버 코드와 SDK 소비자에서 사용하는 API 계약을 비교해 주세요.

이때 Production에 새 프로필을 생성하거나 실제 토큰을 발급하지 않습니다.

## 8. Production Publish 전 충돌 검사

Development의 v3 코드를 Production에 Publish하면 다음 문제가 생기지 않는지 확인합니다.

- v3 데이터 저장 실패
- 기존 QR 토큰 조회 실패
- DB CHECK 제약 오류
- 서버 시작 실패
- 누락된 환경변수
- QR 이미지 생성 실패
- 클라이언트와 서버 API 버전 불일치
- HTTPS 및 QR URL 문제
- CORS 또는 키오스크 프록시 문제
- 기존 프로필 관리 기능 오류

Production에서 사용하는 실제 설정과 Development 설정의 차이를 비교하되, 비밀값은 공개하지 않습니다.

## 9. Development 환경 테스트

Production을 건드리지 않는 범위에서 다음 테스트를 실행합니다.

- TypeScript 타입 검사
- API 테스트
- 프로필 v3 생성·조회
- 60·70·80% 저장·조회
- viewportMode null
- v1/v2 정규화
- 프로필 수정·폐기·재발급
- QR 토큰 유효성
- 프로필 관리 권한 확인
- 프런트엔드 빌드
- 주요 화면의 Preview 렌더링

기존 테스트가 없는 기능은 테스트하지 않았다고 분명히 보고합니다.

Development에서 테스트 데이터 생성이 필요할 경우 실제 운영 데이터가 아닌 격리된 테스트 DB를 사용하고, Production과 연결되지 않았음을 먼저 확인합니다.
