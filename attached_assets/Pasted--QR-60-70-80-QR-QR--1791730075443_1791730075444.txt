# 내 방식 QR — 중앙 접근성 프로필의 하단 조작 모드 60%·70%·80% 선택 기능 구현

현재 '내 방식 QR' 중앙 서비스에서는 사용자가 접근성 설정을 선택하고 QR 프로필을 생성·저장·수정·재발급할 수 있습니다.

데모커피와 무인민원발급기에서는 공통 접근성 SDK v0.5.2를 사용하고 있으며, 개발용 `setViewportMode()`로 화면 아래쪽 60%·70%·80%에서 조작하는 방법 B를 검증했습니다.

이번 작업에서는 중앙 프로필 설정 화면의 기존 '하단 조작 모드' ON/OFF 스위치를 **사용하지 않음 / 60% / 70% / 80% 선택 기능**으로 바꾸고, 선택한 비율을 DB와 QR 프로필 조회 API에 반영해 주세요.

기존 QR은 모두 개발자 개인의 테스트용이며 실제 이용자가 없습니다. 따라서 기존 `bottomControls` 호환성을 유지하기 위한 불필요한 이중 필드 설계는 하지 않아도 됩니다.

단, 현재 저장된 테스트 프로필이 데이터 마이그레이션 중 오류를 발생시키지 않도록 안전하게 처리하고, 기존 프로필을 임의로 삭제하지는 마세요.

## 1. 사용자 설정 UI 변경

현재 '내 설정 관리하기' 화면의 '조작을 편하게 하는 방법' 항목에 다음 설정이 있습니다.

하단 조작 모드
설명: 자주 쓰는 버튼을 화면 아래쪽에 모아요.
현재 UI: ON/OFF 스위치

이를 다음과 같이 변경합니다.

**하단 조작 모드**

설명:
'화면 위쪽에 손이 닿기 어려운 경우, 아래쪽에서 화면을 조작할 수 있어요.'

선택지:

- 사용하지 않음 — 전체 화면 사용
- 아래쪽 60% 사용
- 아래쪽 70% 사용
- 아래쪽 80% 사용

기본 선택은 '사용하지 않음'입니다.

화면을 축소하거나 글씨·버튼 크기를 줄이는 방식이 아니라, 사용할 수 있는 세로 화면 영역을 아래쪽으로 제한하고 그 안에서 스크롤하는 기능임을 사용자가 이해할 수 있도록 설명해 주세요.

### UI 요구사항

- 기존 접근성 설정 화면의 디자인과 일관성 유지
- 큰 글씨와 모바일 화면에서도 모든 선택지 표시
- 각 선택지를 충분히 큰 터치 영역으로 구현
- 선택된 항목을 색상뿐 아니라 테두리·상태 등으로 구분
- 키보드 조작과 스크린리더 접근성 고려
- 다른 설정 항목과의 간격·정렬 유지
- 설정 수정 화면에서도 동일한 선택지 사용
- 별도의 하단 조작 ON/OFF 스위치를 중복으로 남기지 않음

모바일에서 가로로 네 선택지를 억지로 배치하지 말고, 화면 너비에 맞춰 줄바꿈 또는 세로 배치를 허용해 주세요.

## 2. 프로필 데이터 구조 변경

새 하단 조작 모드는 기존 `bottomControls: boolean` 대신 명시적인 `viewportMode` 필드로 저장합니다.

권장 데이터 형식:

사용하지 않음:

```json
{
  "viewportMode": null
}
```

아래쪽 60%:

```json
{
  "viewportMode": {
    "mode": "bottom",
    "heightPercent": 60
  }
}
```

아래쪽 70%:

```json
{
  "viewportMode": {
    "mode": "bottom",
    "heightPercent": 70
  }
}
```

아래쪽 80%:

```json
{
  "viewportMode": {
    "mode": "bottom",
    "heightPercent": 80
  }
}
```

비율은 문자열이 아닌 숫자 60·70·80으로 저장해 주세요.

기존 `bottomControls` 필드는 새 프로필의 정식 설정 구조에서 제거합니다.

서버의 기존 DTO·Zod 검증·TypeScript 타입·DB 저장 구조·API 응답을 살펴보고, 실제 아키텍처에 맞게 일관되게 변경해 주세요.

정식 지원값은 null 또는 위 세 비율뿐입니다.

59, 65, 90 같은 임의의 비율과 잘못된 mode 값은 거부해야 합니다.

## 3. 프로필 스키마 버전 관리

현재 중앙 서비스의 공개 프로필 스키마가 v2라면, 이번 변경을 **v3**로 올려 주세요.

v3의 핵심 변경은 다음과 같습니다.

- `bottomControls` 제거
- `viewportMode` 도입
- 지원 비율 60·70·80%
- 비활성 상태는 null

기존 v1/v2 프로필과 관련한 데이터 마이그레이션은 필요한 최소 수준으로 수행합니다.

기존 QR은 전부 내부 테스트용이므로 기존 하단 조작 값의 동작을 재현할 필요는 없습니다.

기존 boolean 값은 마이그레이션 시 임의로 60%·70%·80% 중 하나로 해석하지 말고, `viewportMode: null`로 처리해 주세요.

다른 접근성 설정값은 가능한 한 보존합니다.

QR 토큰이나 프로필 ID는 불필요하게 변경하지 마세요.

기존 저장 데이터를 삭제하거나 데이터베이스를 초기화하지 마세요.

이미 있는 테스트 프로필을 조회·수정할 수 있는지 검증해 주세요.

## 4. 데이터베이스 및 API 반영

다음 흐름에서 `viewportMode`가 정확히 저장되고 다시 조회되어야 합니다.

1. 새 접근성 프로필 생성
2. 하단 비율 선택
3. 프로필 저장
4. QR 발급
5. QR 토큰을 이용한 프로필 조회
6. 저장된 비율 확인
7. 기존 프로필 수정
8. 변경된 비율 저장
9. 같은 QR로 다시 조회
10. 프로필 폐기·재발급 과정에서도 설정 유지

QR 이미지 안에 모든 설정을 직접 넣는 방식으로 변경하지 마세요.

기존처럼 QR은 서버의 프로필을 조회하는 토큰·링크를 담고, 실제 설정값은 중앙 서버에서 관리하는 구조를 유지합니다.

기존 조회 토큰만으로 프로필 수정·폐기 권한을 얻을 수 없도록 하는 보안 구조도 유지해 주세요.

## 5. QR 조회 API 응답

키오스크가 중앙 서버에서 프로필을 조회하면 다음과 같은 v3 프로필을 받을 수 있도록 해 주세요.

```json
{
  "schemaVersion": 3,
  "settings": {
    "textSize": "extraLarge",
    "buttonSize": "large",
    "contrast": "high",
    "easyLanguage": false,
    "viewportMode": {
      "mode": "bottom",
      "heightPercent": 70
    },
    "smartGuide": true,
    "guideDelaySeconds": 10,
    "voiceGuidance": false
  }
}
```

위 코드는 핵심 필드를 설명하는 예시입니다. 실제 API에 기존 토큰 정보나 메타데이터가 있다면 기존 응답 구조를 무리하게 바꾸지 마세요.

`updatedAt` 등 기존 메타데이터가 있다면 유지해 주세요.

새 프로필 조회 응답에서 `viewportMode`가 누락되거나 이전 `bottomControls`로 치환되지 않아야 합니다.

## 6. UI 상태와 저장 데이터 일치 검증

다음 시나리오를 확인해 주세요.

- 사용하지 않음 선택 후 저장·재조회
- 60% 선택 후 저장·재조회
- 70% 선택 후 저장·재조회
- 80% 선택 후 저장·재조회
- 60% → 80% 수정
- 80% → 사용하지 않음 수정
- 페이지 새로고침 후 선택 상태 복원
- QR 발급 후 프로필 조회
- 재발급 후 프로필 설정 확인
- 잘못된 비율 값의 서버 검증 실패

UI에 선택 상태만 반영되고 실제 DB에는 저장되지 않는 문제가 없어야 합니다.

## 7. 기존 접근성 설정 유지

하단 조작 모드 외에는 기존 기능을 변경하지 않습니다.

반드시 유지할 항목:

- 글씨 크기 기본·크게·아주 크게
- 버튼 크기 기본·크게
- 화면 대비 기본·고대비
- 쉬운 말
- 스마트 길잡이
- 길잡이 대기 시간 10·15·20초
- 음성 안내

- QR 생성·수정·폐기·재발급

특히 이전에 제거했던 '화면 단순화' 설정을 복원하지 마세요.

## 8. 미리보기 기능

중앙 서비스에 기존 실시간 접근성 미리보기가 있다면, 하단 조작 선택 상태를 미리보기에도 반영해 주세요.

단, 중앙 프로필 설정 페이지 전체를 실제 키오스크처럼 60%로 줄일 필요는 없습니다.

미리보기 영역 안에서 다음 차이가 이해되도록 해 주세요.

- 사용하지 않음: 전체 높이 사용
- 60%: 아래쪽 60% 영역 사용
- 70%: 아래쪽 70% 영역 사용
- 80%: 아래쪽 80% 영역 사용

글씨나 버튼의 크기를 비율에 맞춰 축소하는 시각화는 금지합니다.

이미 있는 미리보기 컴포넌트를 최대한 재사용하고, 불필요한 장식이나 애니메이션은 추가하지 마세요.

미리보기 영역이 작아 실제 비율을 정확하게 표현하기 어렵다면, 거짓으로 정확한 작동을 묘사하지 말고 선택된 비율을 설명하는 간단한 시각화로 처리해 주세요.

## 12. 키오스크 SDK와의 관계

현재 데모커피와 무인민원발급기에 설치된 SDK는 v0.5.2입니다.

이 버전은 직접 `setViewportMode()`를 호출하면 방법 B를 실행할 수 있지만, 새 QR 프로필 v3를 자동 해석하도록 연결된 상태는 아닙니다.

따라서 이번 작업에서는:

- 중앙 서비스의 v3 프로필 생성·저장·조회 구현
- QR 조회 응답에 viewportMode 포함
- 실제 키오스크 화면에 새 설정을 적용하는 것은 후속 SDK 작업으로 분리
- 데모커피와 무인민원발급기 프로젝트 수정 금지
- SDK 패키지 내부 변경 금지

중앙 프로필 저장과 실제 키오스크 적용을 혼동하지 마세요.
