# 내 방식 QR 중앙 서비스 — 체험형 미리보기 및 스크롤 안내 설정 추가를 위한 구조 조사

현재 프로젝트는 중앙 QR 설정 서비스 **‘내 방식 QR’ Replit**입니다.

이번 작업은 앞으로 구현할 기능들의 현재 구조를 확인하는 **읽기 전용 조사**입니다.

**코드·DB·API·UI·설정값을 수정하지 마세요. 테스트 QR을 새로 생성하거나 Publish하지 마세요.**

## 1. 확정된 개발 방향

앞으로 다음 기능을 구현할 계획입니다.

### A. 세로형 체험 미리보기

현재 정사각형에 가까운 QR 설정 미리보기를 실제 키오스크에 가까운 세로형 9:16 비율로 개선합니다.

단순한 그림이 아니라 사용자가 접근성 기능을 직접 연습할 수 있는 미리보기입니다.

### B. 쉬운 말 안내 체험

- 쉬운 말을 켜면 미리보기 상단에 안내창 표시
- 실제 SDK처럼 이전·다음 버튼과 페이지 번호 제공
- 사용자가 직접 페이지 이동 가능
- 접기·펼치기 버튼 없음
- 안내 문구는 이해하기 쉬운 예시 사용
- 스마트 길잡이가 종료되면 이전에 보던 쉬운 말 페이지 복귀

### C. 스마트 길잡이 체험

- 스마트 길잡이 설정 ON일 때 선택된 지연 시간 10·15·20초 후 등장
- 한 페이지 일반 안내는 10초 표시
- 두 페이지 일반 안내는 총 15초 표시하며 약 7.5초 후 페이지 전환
- 느린 안내는 총 20초 표시하며 두 페이지면 약 10초 후 전환
- 스마트 길잡이에는 X 버튼만 있고 접기·펼치기 버튼 없음
- X를 누르면 즉시 닫히고 기존 쉬운 말 페이지 복귀
- 자동 종료 시에도 기존 쉬운 말 페이지 복귀
- X로 닫은 뒤 같은 체험에서 자동 재등장하지 않음
- 스마트 길잡이 설정을 OFF 했다가 다시 ON 하면 선택된 등장 지연부터 새 체험 시작
- 별도 ‘다시 연습하기’ 버튼은 만들지 않음

미리보기 바깥에는 다음과 같은 연습 안내 문구를 적절히 배치할 예정입니다.

- “다음 버튼을 눌러 이어지는 설명을 읽어보세요.”
- “스마트 길잡이가 나타나면 X 버튼을 눌러 닫아보세요.”
- “스마트 길잡이를 닫으면 읽던 쉬운 말 안내로 돌아와요.”

### D. 쉬운 말과 자동 하단 80%

실제 SDK 정책:

- easyLanguage:true + viewportMode:null → 자동 하단 80%
- 명시적 하단 60·70·80% → 사용자가 선택한 값 유지
- easyLanguage:false + viewportMode:null → 기본 레이아웃

현재 중앙 사이트 미리보기에는 쉬운 말을 켜고 하단 조작 모드를 사용하지 않았을 때 자동 80%가 반영되지 않는 문제가 있습니다.

향후 미리보기는 실제 SDK와 일치시켜야 합니다.

단, 자동 적용을 이유로 저장값 viewportMode:null을 임의로 80%로 바꾸지 않습니다.

### E. 아래쪽 내용 안내 — 실제 QR 설정 신규 추가

사용자용 이름: **아래쪽 내용 안내**

설명:
“화면 아래에 더 볼 내용이 있으면 알려줘요. 끝까지 내리면 안내가 사라져요.”

ON/OFF 설정을 QR 프로필에 추가할 예정입니다.

**확정된 기본 정책:**

- 새 QR 생성 시 기본값 OFF
- 기존 QR에 설정 필드가 없으면 OFF
- QR 없이 키오스크 사용 시 OFF
- QR에 명시적으로 ON이 저장된 경우에만 스크롤 안내 표시
- 명시적으로 OFF가 저장된 경우 표시하지 않음

스크롤 안내는 일반 스크롤 콘텐츠 위에 겹쳐 표시될 수 있습니다. 이는 정상 동작입니다.

그러나 QR 도크, footer 같은 고정 조작부와 겹쳐 버튼 글씨를 가려서는 안 됩니다.

미리보기에서는 ON일 때 안내를 표시하고, 사용자가 실제로 내용을 맨 아래까지 스크롤하면 안내가 사라지는 동작을 연습할 수 있어야 합니다.

미리보기 주변에는 다음 문구를 추가할 예정입니다.

“화면을 끝까지 내리면 아래쪽 내용 안내가 사라져요.”

### F. AI 추천 연결

아래쪽 내용 안내를 실제 QR 설정으로 추가하면 기존 AI 추천 기능에도 반영할 예정입니다.

예상 질문:

“화면 아래에 더 볼 내용이 있다는 안내가 필요하신가요?”

AI 추천 결과에 따라 설정이 ON/OFF로 제안될 수 있지만 사용자는 최종 설정을 직접 변경할 수 있어야 합니다.

AI 추천을 이용하지 않는 사용자의 기본값은 OFF입니다.

## 2. 조사할 현재 코드 구조

다음 항목의 실제 구현 파일과 연결 관계를 조사하세요.

### 설정 화면

- 접근성 설정 항목을 렌더링하는 컴포넌트
- easyLanguage, smartGuide, guideDelaySeconds, slowGuidance의 상태 관리
- viewportMode 선택 UI 및 저장값
- 각 설정의 기본값
- 설정 변경 후 미리보기에 반영되는 흐름

### 현재 미리보기

- 미리보기 컴포넌트와 CSS 위치
- 현재 화면 비율과 크기 제한
- 현재 구현된 접근성 설정 반영 범위
- 하단 60·70·80% 레이아웃 계산 방식
- 쉬운 말 자동 80%가 미리보기에 누락된 정확한 원인
- 미리보기 안의 버튼·스크롤 가능 여부
- 상단 안내 영역을 추가할 수 있는 현재 구조
- 실제 키오스크 SDK를 사용하는지, 중앙 사이트 자체 구현인지

### QR 프로필 데이터

- 프로필 TypeScript 타입 및 스키마
- 생성·수정·조회 API
- DB 저장 구조
- QR 응답 생성 과정
- 기존 QR의 누락 필드 기본값 처리
- 새 boolean 설정 추가 시 변경이 필요한 파일
- 기존 테스트 QR에 대한 DB 마이그레이션이 실제로 필요한지

기존 QR은 모두 테스트용이므로 이를 보존하기 위해 불필요하게 복잡한 마이그레이션을 설계하지 마세요. 다만 이번 조사는 읽기 전용이므로 삭제·초기화도 금지합니다.

### AI 추천

- 현재 AI 추천 기능의 실제 구현 여부
- AI 추천 질문·선택지·응답 처리 코드
- 추천 결과를 프로필 설정으로 변환하는 과정
- 새 boolean 설정을 추가할 경우 필요한 변경점
- AI 추천이 미연결·규칙 기반·외부 API 방식 중 무엇인지 확인

**실제로 없는 기능을 있다고 가정하지 마세요.**

## 3. 다른 프로젝트와의 연결 확인

중앙 QR 사이트와 공통 SDK의 역할을 구분하세요.

- 중앙 QR 사이트: 설정 UI, 미리보기, 프로필 저장·조회
- 공통 SDK: 키오스크에서 실제 접근성 설정 적용
- 데모커피 및 무인민원발급기: 공통 SDK를 설치해 사용하는 호스트

중앙 사이트에 아래쪽 내용 안내 설정만 추가해도 실제 키오스크에서는 작동하지 않으므로, SDK에도 새 설정을 해석하고 스크롤 안내를 ON/OFF하는 수정이 필요할 예정입니다.

현재 공통 SDK 안정 버전은 **v0.5.29**입니다.

다음 기능 변경 버전은 **v0.5.30**으로 관리할 계획입니다.

중앙 QR 사이트에서 확인 가능한 API·스키마 구조와 SDK에 필요한 인터페이스 변경안을 정리하세요.

단, SDK 코드를 임의로 수정하지 마세요.
